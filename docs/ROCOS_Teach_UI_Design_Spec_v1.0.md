## 1. 设计目标与原则

ROCOS HMI 定位为集**机器人状态查看、手动示教、程序编程、运行调试、IO 与设备、监控诊断、系统配置**于一体的示教平台。

1. **卡片化与模块化**：所有主要功能通过独立的圆角矩形卡片组织，每张卡片有明确标题、内容区域和上下文操作。
2. **操作优先，状态常驻**：突出当前任务的操作控件；连接、控制权、使能、模式、安全状态及报警信息始终可见。
3. **3D 按需呈现**：三维视图是核心卡片之一，但不强制占据所有页面的主体空间。
4. **一致的导航语义**：左侧一级 TAB 切换工作场景；卡片内二级 TAB 切换同类功能；底部快捷卡片切换辅助信息。
5. **响应式重排，而非整体缩放**：以 1920 × 1200 为默认设计基准，按照可用 CSS 视口宽度重新编排卡片。
6. **兼顾触控与安全**：适合鼠标、键盘和触摸交互；软件交互不得被当作硬件安全功能的替代品。

## 2. 已定稿的信息架构

### 2.1 一级导航：固定 7 个 TAB

| 序号 | 中文名称 | 英文标识 | 主要功能 | 建议的二级 TAB |
|---|---|---|---|---|
| 1 | 总览 | Dashboard | 机器人与系统摘要、常用入口 | 以信息卡片为主，不强制设置二级 TAB |
| 2 | 手动示教 | Teaching | 关节/TCP 点动及点位记录 | 关节点动、笛卡尔点动、零空间、示教点 |
| 3 | 程序编程 | Programming | 创建与编辑机器人程序 | 程序管理、图形化编辑、Lua 编辑、变量与点位 |
| 4 | 运行调试 | Execution | 执行、单步、轨迹预览及仿真 | 程序执行、单步调试、轨迹预览、离线仿真 |
| 5 | IO 与设备 | Devices | IO 及外部设备监控操作 | 数字 IO、模拟 IO、末端工具、外部设备 |
| 6 | 监控诊断 | Diagnostics | 运行数据、报警、日志 | 实时状态、数据曲线、报警记录、系统日志 |
| 7 | 系统设置 | Settings | 机器人、工具和系统配置 | 机器人参数、工具/工件坐标系、负载、阻抗、安全、网络、用户 |

**划分原则（已定稿）**：轨迹仿真归入“运行调试”；报警诊断与实时监控合并为“监控诊断”。二级 TAB 名称和数量可在详细设计阶段微调，不新增一级导航。

### 2.2 三层导航与切换方式

- **一级：左侧导航栏**。切换总览、示教、编程等完整工作场景。
- **二级：卡片顶部 TAB / Segmented Control**。在原位置切换同类功能，例如关节点动、笛卡尔点动、零空间点动；其余卡片及 3D 场景保持稳定。
- **快捷层：工作区底部辅助信息卡片**。候选内容固定为：**示教点、程序、IO、报警、日志**。切换辅助信息不跳出当前一级页面。

底部另设独立的**全局运行控制条**（参见第 3 节），它与“可切换辅助信息卡片”是两个不同区域，不应合并。

## 3. 全局布局规范

### 3.1 标准设计画布（已定稿）

- **默认画布**：1920 × 1200，比例 **16:10**。
- 此画布是**初始设计与验收基准**，**不是固定窗口尺寸**；不要把整个页面用 CSS `transform: scale()` 等方式缩放以适配其他屏幕。
- 响应式判断基于浏览器的 **CSS viewport**，不以设备物理像素作为断点。

### 3.2 全局区域

| 区域 | 默认规格 | 是否常驻 | 设计要求 |
|---|---|---|---|
| 顶部全局状态栏 | 高 64 px | 是 | 设备、连接、控制权、使能、模式、安全、速度、报警等关键状态 |
| 左侧一级导航栏 | 宽 200 px；折叠后约 64 px | 桌面/横屏常驻 | 图标 + 标题；折叠时显示图标及可访问的文本提示 |
| 主工作区 | 剩余空间，**12 列响应式 CSS Grid** | 是 | 根据一级 TAB 加载对应卡片组合 |
| 工作区底部辅助卡片 | 高度随视口和内容调整 | 按页面需要 | 示教点/程序/IO/报警/日志之间切换，支持折叠 |
| 底部运行控制条 | 高 72–80 px | 支持操作的页面常驻 | 运行、暂停、停止、速度及上下文快捷操作；状态无效时禁用并说明原因 |

**布局规则**：主工作区外围留白、卡片间距及卡片内边距分别设置；顶部状态栏与运动控制条的可见性优先于非关键内容。屏幕高度不足时，优先让卡片内部滚动或折叠辅助区域，不裁切操作控件。

### 3.3 全局状态栏信息

必须持续可见的项目：**连接状态、机器人设备、控制权归属、使能状态、工作模式、硬件安全状态、速度倍率、当前最高报警等级/数量**。时间、用户身份、快捷设置等次要信息可随宽度收敛到菜单内。

状态栏应区分“已连接 / 断开”“已使能 / 未使能”“控制权：本机 / 他端 / 无”“手动 / 自动”等，不能只依靠颜色表达状态。

## 4. 视觉设计规范

### 4.1 整体风格（已定稿）

- **深蓝色**顶部状态栏与左侧导航栏。
- **白色为浅色主题基底**；浅灰/浅蓝灰仅用于卡片间隔、次级容器及 3D 地面，形成白底上的层次。
- **白色圆角矩形卡片**承载主要内容。
- **蓝色强调**当前选中的 TAB、主要操作按钮和选中数据。
- 清晰分区、轻边框、克制的阴影，优先呈现数据与操作，而非装饰效果。
- 默认浅色工作区；保留深色模式扩展能力。

**本轮风格提案：蓝灰精密工作台（待确认）**。科技感来自规则网格、清晰的数据对齐、细线图标、蓝色选中态及简洁的机器人三维视图。界面采用平面化工业仪表风格，不使用霓虹描边、整屏网格、玻璃模糊、装饰扫描线或循环发光；信息密度服务于操作，不追求填满每个区域。深蓝导航保持原设计基线，浅色内容区以白色为视觉主体。

**设计依据与取舍**：使用仓库内 [ui-ux-pro-max](../.agents/skills/ui-ux-pro-max/SKILL.md) 检索设计系统，并针对工业仪表盘、减少动态效果和 React Effect 清理做补充检索。采纳 `Minimalism & Swiss Style` 的清晰层级及 `Data-Dense Dashboard` 的网格/数据组织建议；不采纳自动输出中的营销型 Hero/CTA 布局、绿色主强调色和远程字体。以下蓝灰配色是结合本项目需求制定的方案，不宣称是技能数据库直接给出的专属机器人配色。React 检索包含较新版本建议，本项目保持 React 18 的 `useEffect`/清理机制，不引入 React 19 专用 API。

**字体统一为强制约束**：所有 UI 文本统一使用 [public/fonts/](../public/fonts/) 下的 **AlibabaPuHuiTi**，不按语言、页面或数据类型切换字体。关键数值可启用该字体自身支持的等宽数字特性；角度、长度、速度、力矩均需显式显示单位。图标配合文本/Tooltip 使用，不能只凭颜色判断状态。

**颜色使用约束**：蓝色表示选择、焦点和常规主操作，不表达“机器人安全”；绿色只表达已确认的正常/成功状态，琥珀色表达警告，红色表达故障和停止。断线/未知必须显示文字，不沿用最后一次绿色状态。普通文本与底色对比度目标 ≥ 4.5:1，必要的控件边界、状态图标和焦点指示目标 ≥ 3:1；低对比度装饰分隔线不能成为唯一状态提示。

按不透明 sRGB 色值计算：白字/主蓝约 **5.17:1**，主文字/白底约 **14.68:1**，次级文字/白底约 **4.76:1**，成功文字/浅绿底约 **4.79:1**，警告文字/浅黄底约 **6.84:1**。`#64748B` 不作为浅灰容器的普通正文色，`#DC2626` 不作为浅红底的普通正文色，分别使用专门的 `--color-text-on-muted` 与 `--color-danger-text`。实现中的透明叠加、Hover 和禁用状态仍需按最终背景检查。

### 4.3 卡片组件统一规则

1. 每张卡片由**标题栏、内容区、可选工具栏/操作区**组成。
2. 同类数据使用统一的标签、单位、对齐方式；数值实时更新时避免布局抖动。
3. 支持卡片内 TAB、展开/折叠、有限的尺寸调整；首次进入页面采用系统推荐布局。
4. 辅助卡片允许切换与折叠，**运动控制卡片不允许因自由拖拽而意外隐藏或遮挡**。
5. 重要错误和失联提示不得被卡片滚动或 3D 遮挡。
6. 3D 卡片支持放大/全屏，但必须保留必要的运行与安全状态可见性。

### 4.4 字体、标题层级与密度（字体和字号为强制约束）

| IO 与设备 | 数字输入/输出、模拟量、末端工具配置、外设卡片 | 信号/设备字段为正文 14 px |
| 监控诊断 | 曲线卡片、报警历史、日志 | 图表内标题 14 px；坐标刻度 12 px |
| 系统设置 | 工作空间、关于、阻抗配置 | 阻抗参数分组；关于品牌为非标题展示文字 |
| 全局 / 弹出层 | 连接、模型加载、曲线设置、确认对话框与抽屉标题 | 顶部状态值和底部操作为正文；导航 14 px；辅助标签 12 px |

**盘点记录**：改造前源文件的数字字号声明涉及 18 种值（10、11、12、13、14、15、16、17、18、20、21、22、24、26、28、32、44、70 px，包含图标）。问题包括：Ant Design 基准 15 px 与工作区 14 px 不一致；卡片标题在窄屏降为 14 px；机器人名 24/20 px、程序名 22 px、Lua 小标题 13 px；来源/时间戳仅 10–11 px。文字现统一映射至上述令牌。图标、点动 ± 符号和 3D 空间标签的几何显示尺寸不属于文字层级，不通过全局字体规则改变图标大小。

**实现与验收要求**：`src/styles/typography.ts` 是唯一数字字号来源，启动时注册 `--font-*`，Ant Design 主题、ECharts、Blockly 和 3D 标签引用同一份配置；普通 CSS/内联样式使用语义变量。新增文字不得自行写入 10/11/13/15/22/24 px 等局部字号；禁止断点内缩小同层级标题和正文。编辑器/Blockly 用户主动缩放不在此限制内。所有主题与中英文按同一规范检查，并覆盖弹窗 Portal。普通标题不使用浏览器默认 h3/em 比例。

- 正文使用 AlibabaPuHuiTi Regular，标题与操作标签使用 Medium/SemiBold；卡片内不足时重排或内部滚动，页面及底部控制栏布局保持稳定。
- 数据行高建议 40–44 px，含操作时 ≥ 48 px；点动按钮保留现有至少 44 × 44 CSS px 触摸目标，不因字号统一而缩小按钮。
- 数值可设置 `font-variant-numeric: tabular-nums`，并验证本地字体是否支持；若不支持，仍保持 AlibabaPuHuiTi，通过固定数值容器宽度、右对齐及独立单位列减少布局抖动，不改用其他等宽字体。标签左对齐；小数位由数据类型统一定义。
- 采用 4 px 基础间距阶梯：4 / 8 / 12 / 16 / 20 / 24 / 32。默认外围留白 20 px、卡片间距 16 px、卡片内边距 20 px；紧凑视口可降至 16 / 12 / 16 px。
- 同组触控目标之间保留至少 8 px。出现空间不足时先折叠次要数据、重排卡片或内部滚动，不降低点动目标尺寸。

### 4.5 控件与状态外观（推荐方案）

| 组件 | 默认/选中表现 | 交互要求 |
|---|---|---|
| 一级导航 | 深蓝底、浅色线性图标；选中项蓝底白字，附左侧指示条 | 图标 + 名称；折叠后保留可访问名称与当前页语义 |
| 二级 TAB | 白/浅灰容器；选中项浅蓝底、蓝字、指示线 | 切换保留焦点，不移动相邻运动控件 |
| 主操作 | 蓝底白字，用于“记录当前点”“保存”等 | 一个操作组只突出一个主操作；不把蓝色理解为运动许可 |
| 次操作 | 白底、深色文字、明确边界 | Hover/Pressed 使用浅蓝/浅灰底，不改变控件尺寸 |
| 点动按钮 | 明确的 `−` / `+` 及关节/轴标识 | 按下即时实色反馈；可访问名称如“J1 正向点动”；松开即处理停止 |
| 运动停止 | 红色边框/文字，配停止图标和完整文案 | 与运行/暂停保持位置稳定；显示“软件停止 ≠ 安全急停” |
| 状态标签 | 图标 + 文本 + 轻底色 | “已连接”“未使能”“安全未知”等文案不能被圆点替代 |
| 输入与选择 | 标签始终可见；焦点环、单位和错误提示明确 | 错误在字段附近说明；不只依赖 Placeholder |
| 禁用/等待 | 淡底、可读文字、禁用语义；等待显示“处理中” | 原因在旁边显示，触控不依赖 Hover；避免重复提交 |
| 空态/失联 | “暂无数据”或 `—`，说明原因与可用的恢复入口 | 旧值如保留必须标为“已过期”并附更新时间，不表现为实时值 |

图标优先复用项目 `@ant-design/icons` 的同风格线性图标，常规尺寸 20 px、导航 22–24 px。不混用 Emoji 或不同粗细的图标集。选中态、焦点态、按下态必须彼此可区分。

### 4.6 3D、表格与图表视觉

- 3D 卡片使用白至浅蓝灰背景、低对比地面网格和柔和接触阴影。机器人模型可保留真实材质；效果图中的白蓝模型仅示意，不能作为真实 URDF 外观要求。
- XYZ 轴保留明确字母与惯用轴色；这些色彩属于空间语义，不受“蓝灰为主”限制。网格仅存在于 3D 内，不铺满工作区。
- 表头浅灰、行间细线；选中行浅蓝底 + 左侧标识，Hover 不取代选中态。实时值刷新不播放数字翻滚动画。
- 曲线优先使用蓝色及可区分的辅助色，同时提供线型/点型、图例、单位和时间轴；不能仅用多种深浅蓝区分大量关节。

### 4.7 设计令牌落地约定

后续实现时在现有 `src/styles/theme.ts`、`src/styles/global.css` 中集中映射语义令牌与 Ant Design `ConfigProvider` 主题。组件读取统一颜色、圆角、间距与动效令牌，不逐页硬编码。中英文文案统一进入 `src/i18n/index.ts`，英文长标签需重新检查溢出。深色主题另行验证，本轮效果图仅供浅色主题确认。

## 5. 总览页面（Dashboard）

### 5.1 页面定位

总览是**信息中心**，回答“机器人现在是什么状态？当前执行什么任务？是否存在异常？”；以只读数据卡片和快捷入口为主，不堆放复杂运动控件。

### 5.2 默认卡片：7 张（已定稿）

| 卡片 | 核心内容 | 入口/交互 |
|---|---|---|
| 机器人状态 | 初始姿态三维模型、机器人名称、自由度、总质量、序列号、连杆数与来源 | 进入手动示教 |
| 关节状态 | 各关节位置、速度、力矩、状态 | 进入监控 |
| TCP 位姿 | X/Y/Z、RX/RY/RZ、参考坐标系 | 切换坐标系 |
| 最近程序 | 最近打开/修改的程序 | 打开程序 |
| 运行状态 | 当前程序、执行进度、运行时间 | 进入运行调试 |
| IO 状态 | DI/DO 状态摘要 | 进入 IO 与设备 |
| 报警与日志 | 当前报警、最近事件、报警等级 | 查看诊断 |

**1920 × 1200 推荐初始布局**：第一排是「机器人状态、关节状态、TCP 位姿」3 张卡片（各占 4/12 列）；第二排是「最近程序、运行状态、IO 状态、报警与日志」4 张卡片（各占 3/12 列）。可按实际内容高度配置卡片行高，不要求每张卡片强制等高。

**机器人状态卡片**：在线加载当前控制器的 URDF，离线加载带示例标识的本地 Talon URDF/STL。模型独立使用 URDF 零关节初始姿态（mimic 保留描述中的耦合关系），不跟随实时关节运动、不发送运动指令、不共享示教场景的半透明/坐标轴等开关。无地面、网格和辅助轴；以包围盒中心为自转中心，绕 +Z 以约 6°/秒旋转，从 +Z 俯视为逆时针；按完整旋转包围球适配相机，避免旋转时裁切。提供暂停/继续按钮，系统或应用“减少动态效果”开启时停止自转。

右侧名称取 URDF robot.name，自由度统计独立可动关节（不计 fixed/mimic；planar 为 3、floating 为 6），总质量合计所有 link/inertial/mass，单位 kg。任何连杆缺少有效质量时不得将其视为零：总质量显示“未提供”，另显示已定义部分的合计和覆盖连杆数。当前控制器协议不提供序列号，显示“未提供”，禁止虚构设备标识。在线无 URDF 时显示等待提示，不冒用演示模型。模型加载失败显示错误与重试入口；切换来源、断线和离开页面时清理独立模型资源。

### 5.3 页面行为

- 用户可折叠非关键卡片并记住布局偏好。
- 无连接时展示明确的断线状态和重连入口，不填充伪造的实时数值。
- 报警有显著提示，但不应让静态卡片成为执行危险运动的入口。

## 6. 手动示教页面（Teaching）

### 6.1 页面定位

手动示教是主要**操作工作台**，在同页内完成观察、点动、确认位置、选择工具/坐标系及记录点位。

### 6.2 默认卡片组合（已定稿）

| 区域 | 核心卡片 | 内容 |
|---|---|---|
| 左列上方 | **3D 视图** | 模型、视角、TCP/坐标轴、轨迹、场景元素 |
| 左列下方 | **底部辅助卡片** | 默认示教点列表，可切换程序/IO/报警/日志，与 2.2 保持一致 |
| 中列全高 | **实时状态** | 关节位置、笛卡尔位置与姿态、当前参考系 |
| 右列全高 | **运动控制** | 关节/笛卡尔/零空间点动、精确控制、工作模式与单位 |
| 全局标题栏 | **工具与工件坐标系信息** | 当前工具与工件坐标系，不再另设卡片 |

**桌面布局**：三列按 **3D 与示教点 / 实时状态 / 运动控制 = 6:3:3.2** 分配。示教点只占 3D 下方的同一列，收起后仅增大 3D 的可用高度；实时状态和运动控制保持全高且互不移动。点动空间在运动控制卡片内部切换，3D 不因切换而重置。

**实时状态与示教点布局约束（2026-10-20）**：实时状态内部禁止滚动条，须通过分配关节/位姿区域行高和间距容纳完整读数，不能隐藏溢出数据或缩小已统一的字号。工作区宽度不超过 1100 px 或窗口高度不超过 760 px 时，状态改用详情抽屉，运动控制留在 3D 右侧；工作区不超过 700 px 时运动控制移至下方。矮屏抽屉将两组读数并排展示。示教点工具栏按钮统一高 44 px，图标按钮至少 44×44 px；按钮距卡片上下边框至少 8 px，右侧保持内边距，展开和收起时均不得贴边或重叠。示教点列较窄时用带提示的图标按钮，避免工具栏挤压。

### 6.3 点动与示教点交互

- 点动模式：**关节点动、笛卡尔点动**；零空间点动并入笛卡尔区域，位于旋转点动下方，不再单列选项卡。
- 每行采用“负向按钮 — 轴名 — 正向按钮”，负向为红色、正向为蓝色，同时保留明确的 − / + 符号与可访问名称；按钮为 48×44 px，相邻按钮行的净间距至少 16 px，轴名隔开正负按钮，禁止将二者紧贴放置。切换点动空间时必须停止正在进行的点动。
- 笛卡尔点动从上到下排列“平移（X/Y/Z）”和“旋转（RX/RY/RZ）”两组，轴名保留 XYZ 惯用色。参考系选择放在控制模式栏中；旋转图标配合正负号，按右手定则，从正轴端朝原点观察正向为逆时针。位置与姿态数值统一放在实时状态中。
- 关节数应从机器人模型/控制器动态获取，不把 7 自由度写死为通用 UI 前提。
- 总览及实时状态的关节条以零位为基准：零位有固定刻线，负值向左绘制红条，正值向右绘制蓝条，零值不绘制非零长度。按关节名称读取 URDF 限位；对称范围的零位居中，不对称范围按比例偏移，单侧限位也保留零位。旋转关节与移动关节分别采用全局角度、长度单位。缺少有效限位或连续关节采用带明确提示的对称参考范围（至少 ±180° / ±1000 mm，超出时扩展）。实际数值不截断，色条仅在显示边界截断；此范围只用于显示，不改变运动指令或替代控制器限位。
- 连续/步进点动采用清晰的切换控件，速度倍率随时可见。
- 示教点列表支持记录、命名、查看、编辑、删除、预览及添加到程序；变更与真实运动分离确认。
- 原点/回零类操作须区分“回到用户示教位置”和“机械零位/回参考点”，避免概念混淆。

## 7. 响应式布局与 Pad 适配

### 7.1 布局断点（已定稿）

| CSS 视口宽度 | 推荐布局 | 响应策略 |
|---|---|---|
| `≥ 1600px` | 完整桌面 | 三列/多列卡片、展开侧边栏、完整状态栏 |
| `1200–1599px` | 紧凑桌面 | 缩小非核心宽度，必要时两列排布，部分信息折叠 |
| `900–1199px` | Pad 横屏 | 图标侧边栏、双列主卡片、减少同时显示的数据列 |
| `600–899px` | Pad 竖屏 | 单列为主、底部主导航、卡片纵向重排 |
| `< 600px` | 小屏查看 | 以状态查看为主，默认不开放运动操作 |

断点应结合高度、方向、浏览器缩放和实际容器宽度测试。某些 1920 × 1200 的高 DPI Pad 在浏览器中的 CSS 视口可能显著小于 1920 × 1200；因此不能通过物理像素判断它属于桌面布局。

### 7.2 适配优先级

1. 保证全局状态、安全信息和操作权限提示可见。
2. 手动示教优先保证 **3D + 点动**两个核心卡片的可用宽度。
3. 缩窄时按布局断点重排卡片，而不是压缩字体或把整个页面等比缩小。
4. 表格过宽时只在卡片内部横向滚动，并允许收起次要列。
5. Pad 竖屏使用底部一级导航；不得让导航、运行控制、辅助信息三个区域互相覆盖。
6. 控制按钮尺寸满足触控要求；不能把 Hover 设为关键操作的唯一入口。
7. 3D 不可用时，数值状态和控制 UI 仍应独立显示，按控制器许可决定是否允许操作。

### 7.3 本轮效果图中的 Pad 重排方案（待确认）

- 以 **1024 × 768 CSS px** 验证横屏：侧栏收为 64 px 图标栏，3D 与点动并列；实时状态移入“状态详情”抽屉，当前工具/参考系在 3D 内以摘要常显，辅助卡片默认折叠。
- 顶栏空间不足时允许从 64 px 增高为两行，重新计算内容高度；连接、设备、控制权、使能、模式、安全、速度、报警不得被收到二级菜单。用户、时间等次要项优先收敛。
- 低高度优先折叠辅助区域；点动列表可在自己的卡片内滚动，但不能在按住点动时因滚动/重排改变命中目标，取消交互须按第 8 节处理。
- Pad 竖屏底部导航建议显示“总览、手动示教、程序编程、运行调试、更多”五个入口，“更多”承载其余三个已定稿页面，七个场景仍可到达。导航、运行控制条分别占位，并预留 `safe-area-inset-bottom`，不可相互覆盖。该竖屏方案尚待单独效果图验证。

## 8. 全局交互、安全与状态反馈

- 使用**统一的控件禁用与原因提示**：未连接、未使能、无控制权、模式不符、控制器报警、安全条件未满足等情况应明确说明。
- 点动须符合“持续按住、释放停止”的交互语义；处理指针取消、窗口失焦、组件卸载、连接中断及控制权丢失，并在**控制器侧**实现独立超时停止保护。
- 运行、暂停、运动停止属于软件控制命令；**软件停止按钮不等于安全急停**。物理急停、三位置使能装置与安全回路依据设备风险评估实现。
- 运动相关的卡片不能被布局编辑模式意外关闭；不允许仅凭前端显示状态作最终运动许可判定。
- 报警至少区分信息、警告、错误；文字说明与图标同时出现；故障详情和复位条件由控制器真实状态决定。

### 8.1 动效定位与技术选择（Anime.js 已指定）

用户提供的 `https://animejs.com/` 对应 **Anime.js**，npm 包名为 `animejs`，本规范统一使用此名称（非 `animate.js`）。本次仅定义方案，不安装依赖或改动业务 UI。

**全局 UI 动效统一采用 Anime.js**：页面、TAB、抽屉、按钮颜色过渡和成功反馈等需要时间插值的效果，均由统一动效层编排，不另行引入 GSAP、Motion/Framer Motion 或第二套手写 CSS 动画时间线。CSS 负责布局、静态外观及即时的 Focus/Pressed/Disabled 状态；“统一动效库”不意味着所有状态都必须动画。拟按官方当前 v4 API 设计，以 React `useEffect` 与 `createScope({ root })` 限定作用域，卸载时 `scope.revert()` 清理；正式接入时确认版本并锁定依赖。参见 [Anime.js 官网](https://animejs.com/) 与 [官方 React 接入说明](https://animejs.com/documentation/getting-started/using-with-react/)（核对日期：2026-10-20）。

动画的作用是说明“选择切换、内容出现、保存成功”，不模拟机器人真实运动或安全状态。机器人实时姿态由 Three.js / React Three Fiber 渲染，曲线由 ECharts 刷新，均不交给 Anime.js 驱动。不得同时为同一元素的同一属性启用 CSS、Ant Design 内建过渡和 Anime.js 动画。

### 8.2 动效规格表

下表为本项目建议值，需在目标工业终端验证；不是库的默认参数。

| 场景 | 效果与幅度 | 时长/缓动建议 | 边界 |
|---|---|---|---|
| 普通按钮 Hover | 背景/边框颜色过渡 | 100–120 ms，ease-out | 仅支持 Hover 的设备；不放大控件 |
| 普通按钮按下 | 立即出现按下底色，释放后恢复 | 恢复 80–100 ms | 运动按钮释放反馈即时恢复，不等过渡 |
| 一级页面切换 | 非关键内容淡入，最多向上 4 px | 160–180 ms，`out(3)` | 状态栏、运动控件不参与；3D 不因动画重新挂载 |
| 二级 TAB | 选中指示条平移；内容可淡入 | 120–160 ms，`out(3)` | 几何位置和焦点稳定；不播放整页退场 |
| 辅助抽屉 | 容器从边缘移动 12 px 并淡入 | 进入 200 ms，退出 140 ms | 布局空间预留；处理焦点进入、返回及 Esc |
| 辅助卡片展开 | 布局先到最终尺寸，内部内容淡入 | 160 ms | 不逐帧动画 width/height，不挤动点动控件 |
| 记录示教点成功 | 对应新行一次浅蓝强调后恢复 | 240 ms | 成功应来自实际保存结果；失败显示错误 |
| 数据加载 | 延迟显示静态骨架/文字，必要时普通加载指示 | 等待超过 200 ms 才显示占位 | 不做全屏闪烁；不能延后真实结果显示 |
| 报警、断线、权限变化 | 立即更新图标、文字和背景 | 无进入延迟 | 禁止闪烁、排队淡入或自动淡出关键提示 |
| 实时关节/TCP/曲线 | 直接显示最新有效状态 | 不做数值插值动效 | 3D 的数据插值由渲染层单独定义，不能由 UI 动画伪造 |

推荐令牌：`--motion-fast: 120ms`、`--motion-normal: 180ms`、`--motion-overlay-in: 200ms`、`--motion-overlay-out: 140ms`。动效层将令牌转换为 Anime.js 的毫秒参数；表中的 ease-out 采用 `ease: 'out(3)'` 实现。同一视口同时只强调 1–2 个元素，不使用循环装饰、弹跳、弹簧过冲或整页级联延迟。

### 8.3 运动交互与动画隔离

1. `pointerdown`、释放、`pointercancel`、失焦、失联及控制权变化由原有控制链路处理；不能将运动命令、停止命令、心跳或许可判断放在动画完成回调中。
2. 点动与停止按钮不做位移、缩放、退场或延时禁用。正在按住点动时不允许通过动画更换按钮位置；离开页面、切换模式或失去上下文必须触发既有停止/清理流程。
3. 发送中与控制器确认后的状态必须区分；不得因“成功动画已播放”就把未确认请求标成成功，也不得因动效未结束而拒绝处理新状态。
4. 快速重复切换时取消旧动效并呈现最新目标，不排队播放过期状态。避免透明旧面板继续接收事件；只允许当前可见交互区域参与焦点和点击。
5. 动画关闭、库加载失败、页面隐藏或低性能降级时，核心 UI 与运动控制保持可用；功能不能依赖动画实例存在。

### 8.4 减少动态效果、生命周期与性能

- 同时支持系统 `prefers-reduced-motion: reduce` 与产品内“减少动态效果”开关；任一开启即取消非必要位移、缩放和渐变动画，直接显示最终可读状态。用户在动画中途打开此选项时也应即时生效。
- React 18 StrictMode 下验证重复挂载/清理；Effect 只依赖页面/交互目标，不依赖每帧机器人遥测。组件卸载时清理动画、监听器和计时器，恢复最终样式及可访问状态。
- 优先只动画 `transform` / `opacity`；短小背景反馈可例外，但不动画大面积模糊、阴影和布局尺寸。3D 画布不因卡片淡入创建新 WebGL 上下文。
- 在目标工业触摸屏上检查 3D 与动效并发时的输入响应，争取 60 fps；测量帧耗时、长任务和实际交互延迟，不能仅凭开发机流畅判定通过。性能不足时首先关闭装饰动效。
- 静态效果图只能确认构图与视觉，不证明动效时序、触控尺寸、性能和运动停止行为已验收；这些必须在可交互原型和设备联调中验证。

### 8.5 全局动效层的接入细节

- 建议新增 `src/core/motion/` 保存时长、缓动和可复用预设，新增 `useMotionScope` Hook 管理组件内作用域；这些是待创建模块。Hook 接收 DOM root、是否减少动态效果、当前交互目标，返回清理与终止到最终状态的能力。
- Anime.js 只修改展示层属性；React 管理组件是否存在、展开状态、焦点、ARIA 与业务结果。关闭抽屉时先禁用旧内容交互，动画结束再卸载视觉容器；用户开启减少动态效果或触发中断时直接完成关闭与焦点返回。
- Ant Design 先通过 `ConfigProvider` 的 `theme.token.motion: false` 关闭可配置的内建动效，再逐个检查 Drawer、Modal、Dropdown、Tooltip、Message 等浮层的进入/退出行为。仅在稳定的自有容器或公开 API 上接入 Anime.js，不查询内部私有 DOM 类名来强行接管。缺乏稳定接入点的组件暂用即时显隐。
- Portal 弹层应有各自的 root，不能依靠页面 root 捕获弹层元素。主题、字体和语言上下文必须进入弹层；优先使用处于上下文中的 Ant Design `App`/Hook 消息接口，避免静态消息 API 脱离主题。
- 普通 Hover 动效只在对应元素上创建，重复进入时取消旧实例；运动相关按钮始终采用即时反馈。自动化检查应包含连续点击、快速开关、路由离开和中途禁用动效。

依据：[Anime.js Scope](https://animejs.com/documentation/scope/)、[Ant Design 主题、上下文与关闭动效](https://ant.design/docs/react/customize-theme/)。官方主题页包含新主版本能力，实现只采用项目当前 Ant Design 5 可用的 API，不同时迁移到新主版本。

### 9.2 React 与 Vue 的选择

**结论：建议继续使用 React + TypeScript + Vite，首期不迁移 Vue。** 当前需求主要是页面结构、主题、交互和数据更新路径的改造，尚无证据表明必须更换框架才能达成。两者均可构建此类界面；这里的选择基于现有代码复用成本，不是声称 React 在所有场景都比 Vue 快。

| 评估项 | 保持 React | 迁移 Vue 3 |
|---|---|---|
| 现有 UI | 可重组 Ant Design React 组件及 TSX | 页面、事件和组件封装需迁移到 Vue 组件 |
| 状态与生命周期 | 保留 Zustand 与现有连接/控制 Hooks，逐步修正订阅范围 | 需迁移订阅、生命周期与状态接入；核心 TS 模块可继续复用 |
| 3D | 复用 React Three Fiber、drei、现有场景组件 | Three.js、urdf-loader 可复用，但 R3F 组件不能直接作为 Vue 组件使用，需要另写场景适配 |
| 曲线与动效 | 复用 echarts-for-react，接入 Anime.js scope | ECharts/Anime.js 核心可用，React 包装层需更换 |
| 交付风险 | 可分页面实施，沿用控制回归用例 | 同时重做 UI 与生命周期，需扩大控制、连接及卸载回归范围 |
| 适用前提 | 当前仓库继续演进 | 团队明确长期只维护 Vue，且愿意承担完整迁移与验收成本时再评估 |

架构建议保留 **React 18 + R3F 8** 当前组合，React/R3F/Three.js 的大版本升级独立立项，避免与 UI 重构混做。Vue 的响应式模型和单文件组件是可行替代，但不能自动解决高频数据广播、图表全量刷新或 WebGL 资源管理问题。

**版本依据**：截至本轮核对，锁文件为 React `18.3.1`、R3F `8.18.0`、Three.js `0.160.1`、urdf-loader `0.13.1`、ECharts `5.6.0`、echarts-for-react `3.0.6`、TypeScript `5.9.3`、Vite `5.4.21`。`package.json` 中的范围不等于实际安装版本；以上仅记录基线，不表示这些是最新版本，也不授权本轮升级。

参考：[Vue 官方简介](https://vuejs.org/guide/introduction.html)、[React Three Fiber 性能建议](https://r3f.docs.pmnd.rs/advanced/pitfalls)。结论来自当前仓库的组件、Hooks 与依赖审查。

### 9.3 应用分层、导航与状态边界

| 层次 | 职责与建议位置 | 不应承担的职责 |
|---|---|---|
| 应用外壳 | `AppShell`、全局状态栏、导航、运行控制条、主题/语言/动效上下文 | 每次切页重建连接和心跳 |
| 页面层 | 总览、示教、编程、运行、设备、诊断、设置；建议放入 `src/pages/` | 自行创建另一套控制器客户端策略 |
| 功能组件 | 原有 `src/components/` 中的点动、表单、曲线、编辑器；封装统一卡片容器 | 直接拼接 API 协议或跨模块修改 DOM |
| 状态与应用服务 | Zustand 选择性订阅；控制器最新状态、编辑草稿、布局偏好分别管理 | 让每条遥测数据引起整个 AppShell 重渲染 |
| 协议与模型 | `src/core/` 的 REST、WebSocket、心跳、单位转换、URDF、数据校验 | 根据动画完成事件判断运动成功 |
| 高频缓冲与渲染 | 曲线环形缓存、批量更新、R3F `useFrame`；独立于 UI 全量状态刷新 | 把全部历史采样复制进 React props 并逐点更新 |

建议增加 React Router 的 **Declarative** 路由层，七个页面分别对应 `/dashboard`、`/teaching`、`/programming`、`/execution`、`/devices`、`/diagnostics`、`/settings`。若控制器静态服务不能处理 SPA 路径回退，首期使用 HashRouter，地址如 `/#/teaching`；服务器明确支持时再用 BrowserRouter。地址恢复只恢复页面/筛选条件，不自动恢复运动或执行程序。

连接与 `ControlHeartbeat` 由应用级生命周期持有，离开某个页面不会创建第二条连接；离开示教上下文须结束当前点动。区分“用户暂停图表显示”“暂停采集”“暂停机器人程序”，三者不能共用一个状态开关。

UI 偏好可持久化，但控制权、使能、运行结果、连接凭据及机器人实时状态不得从布局缓存恢复。重连后重新核实控制器状态；运行、点动、写 IO 等命令不进入通用自动重试队列。网络请求成功与设备已到达目标状态分别显示。

参考：[React Router Declarative 接入](https://reactrouter.com/start/declarative/installation)。本阶段采用客户端路由，不引入 SSR、Next.js 或微前端。

### 9.4 Three.js 与 urdf-loader：复用边界和改造点

**已明确复用**：Three.js 提供三维渲染，urdf-loader 解析 URDF；React Three Fiber/drei 保持现有 React 场景组织方式。不替换为另一套三维引擎。

| 当前模块 | 可复用内容 | 本轮设计要求对应的后续工作 |
|---|---|---|
| `src/core/UrdfModelLoader.ts` | URDF 解析、`package://` 路径处理、经控制器 mesh 接口加载 | 保留现有接口；补充加载进度、部分 mesh 失败与重试展示 |
| `src/scene/RobotModel.tsx` | 关节名映射、模型更新、线框和坐标轴 | 减少高频 React 订阅；审核异步取消、几何体/材质/纹理释放 |
| `src/scene/RobotViewer.tsx` | Canvas、相机、OrbitControls、容器尺寸适配 | 包装为 `Robot3DCard`，接入白底主题、DPR/性能配置 |
| `CameraPresets`、`TrajectoryLine`、`SceneHelpers` | 视角、轨迹、地面辅助显示 | 复用并统一工具栏、图例和显示开关 |
| `SceneErrorBoundary` | WebGL 异常隔离 | 提供数值视图和明确恢复入口，3D 失败不吞掉全局状态 |

具体约束：

1. 同一示教页面内切换关节/TCP/零空间及辅助 TAB，不改变模型 key、不重新下载 URDF、不重置相机。跨一级页面保留相机与显示偏好；首期只维持一个活动主 3D 画布，总览缩略图优先用静态预览。
2. 在 R3F 管理的 `useFrame` 中读取最新姿态快照或 ref 并更新已存在的对象，不额外启动第二个渲染循环。现有 `RobotModel` 对整个 `robotState` 的响应式订阅应改为面向高频读取的方式，避免每个遥测包重渲染组件。
3. 按机器人模型/控制器提供的关节名关联，而不是用数组顺序写死；内部保持接口约定的 rad、m 和四元数，UI 边界转换为 °/mm。未知关节、缺失值和过期状态需要明确标识，不能填充姿态后当作真实数据。
4. 按设备能力控制 DPR、阴影及轨迹点数；初始 DPR 上限建议 1.5，目标终端测试后再调。非可见场景停止无意义的渲染工作，重新显示后读取最新有效姿态，不补播隐藏期间的遥测动画。
5. 区分资源所有权：模型卸载释放专属几何体、材质、纹理和辅助对象；共享缓存需引用计数或统一持有者，避免释放其他视图仍在使用的资源。旧加载任务完成后不得覆盖新设备模型。
6. 轨迹预览/离线仿真使用独立数据源并显示“预览/仿真”，不覆盖实时机器人状态，不发送真实运动命令。urdf-loader 负责模型加载，不提供完整碰撞检测或动力学；这些功能须另有算法/控制器能力才能宣称实现。

依据：[urdf-loader 项目](https://github.com/gkjohnson/urdf-loaders)、[R3F 性能与生命周期建议](https://r3f.docs.pmnd.rs/advanced/pitfalls)、仓库 [API 单位与状态约定](rocos_api.md)。技能检索中的较新 Three.js API 不直接用于当前版本。

### 9.5 曲线方案：继续使用 Apache ECharts

**结论：首期保留 ECharts Canvas 渲染与现有 React 包装层；先优化数据路径，不直接换库。** 用户已确认的常规监控规模适合先用现有方案验证。`EChart` 在本文统一写作官方名称 **Apache ECharts**。

| 候选 | 适合的用途 | 对本项目的取舍 |
|---|---|---|
| ECharts（现有） | 时间序列、缩放、提示、图例及统一监控面板 | 首选；已有组件和配置，集中解决增量更新、单位与交互状态保留 |
| uPlot | 专注时间序列、希望更直接控制绘制与数据的场景 | 性能备选；只有 ECharts 优化后仍未达预算，才用相同数据/设备做对比验证 |
| Chart.js | 常规 Canvas 图表，支持数据预处理/降采样优化 | 可行，但当前没有足以抵消迁移和交互补齐成本的收益证据 |
| 自绘 Canvas/WebGL 曲线 | 特殊波形、大量高频信号等明确的性能需求 | 首期不做；需自行维护轴、命中测试、缩放、图例和可访问替代视图 |

不把第三方 benchmark 的“最快”作为决策依据。uPlot 的替换实验只针对曲线适配层，不要求整个产品同时维护两套默认图表。参考：[ECharts 动态数据](https://echarts.apache.org/handbook/en/how-to/data/dynamic-data/)、[uPlot 官方仓库](https://github.com/leeoniya/uPlot)、[Chart.js 性能说明](https://www.chartjs.org/docs/latest/general/performance.html)。

#### 9.5.1 当前实现与差距

- `plotStore.ts` 当前每通道最多 500 点、10 秒窗口，`appendData` 使用 `Date.now()` 逐点追加、`shift()` 淘汰并复制 Map；这尚不满足 1–10 分钟需求。
- `usePlotDataCollector.ts` 当前在 React Effect 中按每个关节/指标分别写 Store；采集 Hook 位于 `PlotPanel`，且面板固定取前四张图。应将采集提升为应用级订阅，并把同一遥测帧批量写入缓存。
- `RealtimeChart.tsx` 已使用 Canvas、LTTB 与关闭序列动画，但每次重建完整 option 并设置 `notMerge`。需拆分静态配置和数据更新，防止高频全量合并与缩放状态丢失；不能把现有 `large: true` 当成折线性能已优化的证明。
- 当前 HTTP 轮询间隔常量为 20 ms，但这不等于实际获得 50 Hz 的独立控制器采样。WebSocket 推送率、网络抖动和控制器采样能力仍需联调测量。

#### 9.5.2 数据管线与容量

```text
RobotWebSocket / HTTP fallback
  → 协议边界校验、单位与时间戳归一化
  → 最新状态快照（控制/状态显示）
  → TelemetryBuffer.appendFrame（按通道环形缓存）
      → 按可见窗口降采样 → ChartAdapter → ECharts
      → 原始窗口导出 / 后续服务端历史记录
```

| 参数 | 首期方案 | 说明 |
|---|---|---|
| 通道数 | 8–16，可配置 | 指采集信号数量，不要求同一图叠放 16 条曲线 |
| 采样频率 | 10–50 Hz，取实际可获得值 | 记录实际采样间隔、丢帧/断流；低频输入不插值冒充 50 Hz |
| 保留窗口 | 1–10 分钟；建议默认 5 分钟 | 环形容量按最大频率与窗口计算，保留时间与显示缩放独立 |
| 图表刷新 | 默认 10 Hz，性能允许可到 20 Hz | 采样与绘图分离；3D 帧率独立 |
| 可见曲线 | 首期最多四个绘图区，总计最多 16 通道 | 同单位可同图；不同量纲分图或显式独立轴 |
| 显示点数 | 按横向像素宽度生成约 1–2 倍点数/通道的初始预算 | 缩放后重取对应原始区间；依据目标设备调整 |

最大常规窗口为 `16 × 50 × 600 = 480,000` 个采样值。若每点用两个 64 位数保存时间和值，纯数据约 **7.68 MB**，尚不含质量标志、降采样结果、图表内部副本和对象开销；不能把它等同于浏览器总内存。优先使用有界 TypedArray 环形缓存或等价有界结构，写入不通过 `shift()` 搬移整个数组。

拟定义 `appendFrame(frame)`、`readWindow(channelIds, range, pointBudget)`、`clearSession()` 等缓冲接口，配置与版本通知放 Zustand，大块可变数组由缓冲服务持有，不直接暴露为共享可修改的组件 props。批量通知可按显示频率合并，报警和许可状态不得随图表批处理延后。

**时间与质量**：按当前 API 将 epoch 秒的 `timestamp` 转为毫秒，同一帧所有通道共用该时间。缺失控制器时间时使用接收时间并记录来源；检测重复时间、倒序、设备时钟跳变和重连会话边界。不得把一帧数据逐通道调用 `Date.now()` 得到的不同时间当作同步采样。缺失值用空值/质量标记表示，曲线断开，不回填 0；当前协议映射中缺失字段默认 0 的逻辑也需在数据入口整改，否则曲线层无法恢复真实的缺失信息。

**采集与过载**：直接在统一接收服务分发每个有效帧，不依赖 React Effect 保证逐帧采集；WebSocket 与 HTTP 回退只保留一个有效状态来源，避免双写。HTTP 请求不得重叠堆积，响应需按会话/时序筛选。缓存只保留配置窗口，界面显示实际覆盖时长；页面隐藏暂停绘图，但浏览器节流意味着前端不能保证后台无损记录。长时间可靠历史记录应由控制器/后端承担。

#### 9.5.3 渲染、交互与导出

1. 保持稳定的图表实例和 `series.id`；常规更新只提交有变化的序列数据，不每批执行全量 `notMerge`。增删通道时明确移除旧序列；不能把面向特定系列的 `appendData` API 默认用于折线。
2. 保留用户的 `dataZoom`、图例开关和冻结窗口；“跟随实时”与“查看历史”明确切换。冻结显示不停止采集，也不等同于暂停机器人。卡片尺寸变化使用 `ResizeObserver` 合并触发 `resize()`，卸载销毁图表与观察器。
3. 普通趋势可用 LTTB；力矩尖峰、限位邻近值等诊断信号优先使用保留桶内最小/最大值的降采样，并独立保留报警标记。降采样仅用于显示，报警判定不读取显示后的曲线数据。
4. ECharts 全局 `animation: false`；不将采样数值 tween 到下一帧。初期沿用 echarts-for-react，必要时封装小型命令式 `ChartAdapter`；引入 `echarts/core` 按需注册折线、网格、提示、图例、缩放及 Canvas renderer，避免重复打包完整引擎。
5. 单位、时间来源、通道名称、有效性和量程统一配置；线色配合线型/图例，不以颜色唯一识别关节。提供暂停跟随、按钮缩放/复位、数值表或选中时刻读数，触控不能只依赖 Hover tooltip。
6. Canvas 不直接读取 CSS 变量作为颜色值；把主题解析为实际色值与 `AlibabaPuHuiTi` 字体名后传入配置，覆盖标题、轴、图例和提示文字。字体加载后触发重绘；主题切换也保留缩放状态。
7. CSV 导出默认导出缓存中选定区间的原始有效采样，包含时间单位/来源、信号单位、质量与会话标识，注明缺失区段；不得把降采样后显示点冒充完整数据。大文件分批处理，避免主线程一次构造超大字符串。

参考：[ECharts 按需引入](https://echarts.apache.org/handbook/en/basics/import/)。本节接口和数值预算为工程设计目标，尚未性能验收。

### 9.6 程序编程：Blockly + 现有 Lua 编辑能力

**用户已确认交互形态**：机器人指令按顺序排列，支持条件和循环积木。建议引入 **Blockly**；首期不引入 React Flow。节点连线式编排适合另一类流程表达，当前需求无需同时维护两个编辑器范式。

- 首批积木建议包括运动指令、等待、IO 读写、变量、条件分支、有限次数循环、子程序调用。具体指令仅从控制器实际支持的 Lua API 中选择，不以示例名称推定后端已经支持。
- 采用 Blockly 自定义机器人积木及 Lua 生成器扩展；内置生成器提供 Lua 5.1 基础，控制器 Lua 版本、函数签名、单位、阻塞/异步行为仍需逐项核对。Blockly 负责编辑和代码生成，真实执行继续经过 `RobotApiClient` 上传/运行协议。
- 图形程序以带 `schemaVersion` 的 Blockly workspace JSON 为可编辑源，附机器人/工具/点位引用及生成器版本；保存时同步生成 Lua 与 block ID → 行号映射。保存与执行分离，修改点位引用或参数后须重新校验，不能静默执行旧 Lua。
- 首期采用**积木 → Lua 单向生成**。Lua 预览默认只读；用户选择转为手写 Lua 时另存副本并明确不能自动还原积木。已有任意 Lua 文件用文本编辑器打开，不承诺通用 Lua → 积木反向转换。
- 图形编辑的撤销/重做使用 Blockly workspace 的机制；草稿保存采用防抖与版本检查。部署到控制器时核对草稿版本和生成代码摘要，避免“屏幕看到 A、实际执行 B”。
- 在独立 React 容器中创建 workspace，容器变化时 resize，离开页面先保存草稿再 dispose 监听器与实例；不按每次 React render 重建。Blockly 内的字体、工具箱、字段编辑浮层均按第 4.4 节设置，并保留触控操作尺寸。
- `package.json` 已声明 CodeMirror 6 相关依赖，但当前 `ScriptEditor.tsx` 实际使用 textarea，不能视为完整编辑器已接入。后续复用已声明依赖接入 EditorView 和 Lua 语言支持；保留现有脚本上传/运行 API，并补齐未保存提示、错误定位和真实运行状态同步。
- 文本编辑器同样使用本地 AlibabaPuHuiTi，需验证比例字宽下的光标、选择、缩进和行号对齐；不以“代码应等宽”为由擅自更换字体。首期不另装 Monaco、浏览器 Lua 执行器或第二个语言服务平台。

工程文件的 JSON 保存接口、程序校验/调试协议尚需与控制器对齐。若后端仅支持 `.lua`，先保存本地草稿并支持工程 JSON 导入/导出，明确本地草稿不等于控制器已保存。前端行号映射不能自行证明控制器支持断点或单步。

参考：[Blockly 代码生成与 Lua 支持](https://docs.blockly.com/guides/create-custom-blocks/code-generation/overview/)、[Blockly JSON 保存/恢复](https://docs.blockly.com/guides/configure/serialization/)。

下表为实施时的依赖计划；本轮仅修改规范，不安装软件包。新增依赖应核对当前维护状态、许可证、浏览器/Node/TypeScript 要求和 peer dependencies，通过锁文件固定实际版本。

| 库/能力 | 决策与阶段 | 具体用途及边界 |
|---|---|---|

| `zod` | 建议新增，协议/工程文件阶段 | 校验导入工程、持久化设置及控制器消息结构；共享 schema，TypeScript 类型不能替代运行时校验 |

| CodeMirror 6 及现有语言模块 | 复用已声明依赖并实际接入 | Lua 编辑与错误显示；直接使用的模块应显式声明，不能只依赖间接安装 |

| Ant Design 表格虚拟化；必要时独立虚拟列表库 | 先复用，性能触发 | 大量日志/报警/点位才启用；先限制条数/分页，不默认再装整套表格系统 |

| `@playwright/test` | 建议新增为开发依赖 | 浏览器流程、Pad 视口、字体加载、动效开关、指针取消及截图回归 |

**校验策略**：Zod 先用在信任边界，不在每个组件中重复解析；高频消息的校验开销需测量。缺字段/未知枚举应形成不可用或未知状态，不自动转成正常、已使能或 0 值。协议类型仍集中在 `src/core/types.ts`；在边界逐步用 schema 推导或校验类型，避免两套定义长期漂移。参考：[Zod 官方说明](https://zod.dev/)。

**暂不引入**：Axios（已有 API 客户端）、RxJS（首期数据管线无需第二套响应式抽象）、通用自动重试层、自由拖拽仪表盘库、前端物理引擎。固定卡片使用 CSS Grid，局部尺寸调整优先利用现有能力。只有明确需要可编辑布局或物理仿真时再单独选型。

**字体依赖收敛**：当前本地字体已在 CSS 注册为 `Alibaba PuHuiTi 3.0`，与规范的 `AlibabaPuHuiTi` 别名不同；实施时一次性统一 `@font-face`、主题、全局样式和第三方组件配置。现有 `@fontpkg/alibaba-pu-hui-ti-3-0` 不作为另一个字体来源，确认无引用后可移除，所有文件继续来自 `public/fonts/`。

| 阶段 | 交付内容 | 完成条件 |
|---|---|---|
| P0：基线 | 记录现有连接/控制回归与依赖版本，固定目标终端配置 | 明确浏览器、CPU/GPU、内存、网络、控制器频率及测试数据 |

| P2：总览/示教 | 重组现有控制组件，封装 Robot3DCard | 模型/相机保持；失焦、取消、断线、权限丢失仍走原控制保护链路 |
| P3：监控 | 应用级采集、有界缓存、增量 ECharts、历史窗口与导出 | 通过下述常规监控负载验证，导出不丢失缓存内原始有效采样 |
| P4：编程/设备/设置 | Blockly、Lua 编辑、工程保存与后端功能对齐 | 同一程序保存/恢复/生成结果一致；未知后端能力不显示为已支持 |

建议先把每阶段作为可独立验证的变更，避免同一批修改同时升级框架、重写通信并更换图表库。

**首期性能验证方案（建议门槛，未实测）**：

- 输入模拟器按 16 通道 × 50 Hz 推送，保留 10 分钟窗口；四个绘图区各显示最多四条曲线，同时展示 3D 并进行 TAB/抽屉操作，持续运行至少 30 分钟。覆盖尖峰、缺失、乱序、时钟变化和断线重连。
- 记录接收量、有效采样量、淘汰量及丢弃原因；窗口填满后缓存容量应有界，内存经过回收后不持续单调增长，图表/模型切换无实例泄漏。
- 在目标终端争取 60 fps；常规交互验收建议帧耗时 P95 ≤ 33 ms、输入到可见反馈 P95 ≤ 100 ms，并单独记录图表更新和长任务。这里是 UI 性能预算，不是运动停止时限或安全认证指标。
- 超预算时依次降低可见点数/图表刷新率、减少 Store 广播和数据复制、调整 3D DPR/阴影，再评估 Worker 或 uPlot。不能先通过降低采样率而不告知用户来掩盖问题。
- CSV 与缓存原始区间核对，时间/单位/缺失标记一致；“停止跟随”后查看窗口稳定，恢复跟随后定位最新数据；背景标签页的采样限制明确显示。

回归保留现有 `npm run test:control`、`npm run test:script` 与 `npm run build`；新增缓冲/时间/缺失值/生成器等纯逻辑用例继续使用现有 Node 测试方式。UI 与 Pointer Events 场景采用 Playwright，运行于 mock 控制器，不能让 CI 浏览器控制真实机器人。浏览器测试不能替代控制器侧超时停止验证。参考：[Playwright 官方文档](https://playwright.dev/docs/intro)。

## 13. 首轮 UI 实现与功能迁移（2026-10-20）

已按本规范实现 React Teach Shell，采用七个 Hash 路由；连接、控制权心跳、WebSocket 和曲线采集由应用外壳持有，切换页面不重新建立控制会话。默认浅色，保留深色主题及中英文切换；所有界面、CodeMirror、Blockly、ECharts 统一使用本地 AlibabaPuHuiTi。页面进入动效由 Anime.js 管理，支持系统及应用内减少动态效果设置。

实现边界：

- `teachStore` 仅保存本地草稿、点位及预览配置，不向 `connectionStore` / `robotStateStore` 注入 fake 状态；页面和卡片分别标注离线演示与示例数据。连接后没有对应 API 的安全及报警状态显示“未知”。
- 点动使用串行请求；指针释放/取消、键盘释放、失焦、隐藏页面、路由卸载、控制权及坐标系变化会停止。晚返回的点动请求完成后再补发停止，失败不自动重启运动。小于 600 CSS px 时禁止启动实机运动，保留停止入口。
- 原有精确运动面板迁移时修正了 rad 输入被再次乘 π 的换算问题，关节输入数量跟随控制器自由度；最终运动范围和权限由控制器校验。
- 曲线采用独立 TypedArray 环形缓存，每通道上限 30,000 个原始样本、最长 10 分钟，绘制节拍 10 Hz；控制器时间回退清空当前采集段，非有限样本以断点呈现。CSV 导出当前所选通道窗口内的原始样本。冻结期间数据仍持续采集，超过缓存保留期的旧样本会淘汰。
- 图形化程序是单向 Lua 预览，尚未支持 Lua 反向转积木、控制器工程存储和调试位置回写。轨迹规划、急停安全链和采样率配置没有由前端示例替代。
- 自动化验证入口：`npm run test:control`、`npm run test:script`、`npm run test:teach`、`npm run test:ui` 与 `npm run build`。UI 测试使用本机 Chrome，控制器测试拦截 REST/WebSocket，不连接实机。

详细操作入口及验证说明见 [ROCOS HMI UI 实现说明](ROCOS_Teach_UI_Implementation.md)。性能指标、触控设备操作体验与真实控制器行为仍按第 9.9 节验收；单元测试覆盖 16 通道 × 50 Hz × 10 分钟缓存上限，不等同于目标 Pad 上的绘图帧率验收。

### 全局单位与控制器连接设置（2026-10-20）

- 运动控制卡片顶部为控制模式栏，包含“控制模式”和“坐标系”，位于点动/精确控制切换上方。卡片宽度与实时状态接近，约为其实宽的 1.07 倍；点动区不再显示单位切换按钮。
- 系统设置新增“单位显示”，按角度、长度、力、力矩、质量五行同时展示，分别选择 deg/rad、mm/m、N/kN、N·m/N·mm、kg/g。选中单位采用蓝色背景、白色文字。选择立即生效并持久保存，断开连接不重置单位。
- 总览、实时状态、示教点位置表、精确控制输入、模型质量、监控曲线与 CSV 单位一致。速度按所选角度单位每秒显示；阻抗刚度和阻尼按力/长度或力矩/角度的组合单位换算。输入目标及控制器参数在底层保持原有物理量，切换显示单位不得改变命令的实际目标。现有本地点位存储格式（mm/deg）与控制器 SI 协议不随显示设置重写。
- 系统设置单列“控制器连接”选项卡，集中显示 IP/主机名、端口、自动加载模型、连接/断开及控制权接管入口。连接按钮按当前字段连接，不再弹窗；字段就地显示验证错误，端口必须为 1–65535 的整数。连接中及已连接时禁用参数编辑，断开后可修改。关闭自动加载模型时不得请求 URDF，在线模型区显示等待状态，不替换为演示模型。

点动区域在较矮窗口内独立滚动，以保留完整按钮尺寸和 16 px 间距；控制模式栏、实时状态与底部操作栏不随点动列表滚动。笛卡尔的平移、旋转、零空间三组按顺序纵向排列，零空间分组使用分隔线；在线无冗余自由度时显示无零空间提示。

标题栏最左侧设备字段不绘制左侧竖线，字段之间的分隔线保留。卡片内容区统一采用内边距令牌，禁止局部覆盖成更紧的布局；工作区宽度不超过 1100 px 或窗口高度不超过 850 px 时采用 20 px，工作区不超过 700 px 时采用 16 px。增加留白不缩小字号或触控目标，实时状态保持完整显示。
