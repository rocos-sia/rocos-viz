# ROCOS HMI API 协议差距分析

> 核查日期：2026-10-23（Asia/Shanghai）。本文是基于当前 HMI 代码与 Apifox 在线定义的评审材料，不是接口规范副本，也不表示控制器已实现本文建议。

## 1. 摘要与证据基线

### 1.1 主要结论

当前协议已覆盖控制权、状态快照、使能与工作模式、主要运动与点动、坐标系管理，以及 Lua 加载、运行和调试。主要问题集中在以下三方面：

1. **现有调用与协议不一致**：当前设置页提交的 `POST /api/robot/impedance` 未定义；`POST /api/robot/workmode` 没有响应体定义，而客户端要求 JSON 响应。旧模型上传组件还使用未定义的 `POST /api/robot/urdf`，但该组件未挂载到当前主路由，不能当作现有页面故障。
2. **已有协议不足以稳定联调**：WebSocket 状态流、运动目标坐标系、速度与 jerk 单位、点动续发与停止语义、任务关联、错误响应和模型版本等约定不足。刚度、阻尼两个在线接口的参数与响应尤其需要整理。
3. **预览功能缺少线上闭环**：示教点库、真实 I/O、工具负载、报警历史和日志尚缺协议支持。执行页既需要接入已有脚本状态协议，也需要补充步骤映射等能力，不能将整页未接入都归为后端缺接口。

建议先消除当前调用歧义，再完善公共契约，最后分阶段支持预览功能上线。不预设下一版 API 版本号。

### 1.3 判断口径与优先级

| 分类 | 含义 |
| --- | --- |
| 协议缺失 | 在本次完整读取的操作集合或相关 schema 中没有定义该能力；不等于控制器一定未实现 |
| 已有协议需升级 | 操作存在，但字段、约束、响应或行为约定不足，或存在明显自相矛盾 |
| 协议已有但前端未接入 | 远端已有相应操作，当前页面或客户端没有接入，优先安排前端工作 |
| 前端问题 | 本地数据模型、固定值或处理流程需要完善，不能仅靠新增 API 解决 |
| 待控制器验证 | 代码注释、兼容逻辑或协议空白涉及实际运行行为，尚未通过控制器验证 |

- **P0**：当前页面存在直接的调用契约冲突，应先确认并解除联调阻塞；不代表已经复现生产故障。
- **P1**：当前控制、状态显示或诊断所依赖的重要契约，建议下一轮完善。
- **P2**：预览闭环、未挂载组件及后续扩展；相关功能上线前仍需完成。

以下建议中的新增路径、字段和行为均为**建议方案**。最终应根据控制器能力确定，并在 Apifox 正式维护、经 MCP 回读验证后才成为契约。

## 3. 现有调用冲突与公共协议升级

### G01 · 阻抗批量设置缺少契约，单参数接口需修订

- **分类 / 优先级**：协议缺失、已有协议需升级、前端问题；**P0**。
- **证据**：`ImpedancePanel.handleApply()` 通过 `setImpedance()` 向 `POST /api/robot/impedance` 同时提交 `joint_space` 和 `cartesian_space`；在线该路径只有 GET。`POST /api/robot/stiffness` 和 `/damping` 使用 query 参数，`id` 和数值均为可选；200 响应只有空对象 schema。damping 的描述仍写刚度，其数值参数也叫 `stiffness`。这些是协议事实，不能据此判定真实控制器的阻尼参数名。
- **影响**：批量应用无法依当前规范实现或生成客户端；拆成多次写入可能出现部分成功；前端固定七个关节、忽略读取结果中的 `valid`，其 base/tool 选择也未发送，不能靠补接口自动解决。
- **建议方案**：定义批量 `POST /api/robot/impedance`，承接现有数据分组，明确关节顺序、数组长度、单位、有效模式、允许范围、是否原子应用及回读结果。参考系只有在控制器确实支持时才加入参数，否则移除无效前端选项。单参数接口统一目标标识和阻尼命名，修正说明、必填性及标准响应；已有参数若已被使用，采用别名与弃用说明迁移，不能直接改名破坏兼容。
- **验收方向**：不同 DOF、无效模式、数组长度不匹配、负值、越界及中途失败均有明确结果；成功后 GET 可核对生效值；前端按真实维度和 valid 显示，不用默认值冒充控制器配置。

### G02 · 工作模式切换未定义响应体

- **分类 / 优先级**：已有协议需升级、待控制器验证；**P0**。
- **证据**：`POST /api/robot/workmode` 的 200 只有“模式切换成功”描述，没有 `content`。`RobotApiClient.request()` 要求非空 JSON，并读取 `success`、`code`、`message`、`data`；模式选择器会进入该方法。
- **影响**：若控制器按空响应实现，UI 会报 `Empty response from server`；若实际返回 JSON，则现有契约无法描述和校验它。尚未对控制器复现此问题。
- **建议方案**：先回查实际响应，再在协议补齐标准 JSON 包装，建议包含切换后的 `work_mode`、`robot_state`；明确返回代表完成还是受理，以及运动中、未使能、状态不允许时的结果。
- **验收方向**：五个模式各有成功示例，非法模式与非法状态有失败示例，真实响应可通过 schema 校验且被现有客户端解析。

### G03 · 遗留 URDF 上传调用无协议

- **分类 / 优先级**：协议缺失、前端问题、待控制器验证；**P2**。
- **证据**：`ModelLoaderPanel.handleUpload()` 调用 `uploadUrdf()`，使用 multipart 字段 `file`，期望 JSON `data.path`。线上 `/api/robot/urdf` 仅 GET。当前主路由没有导入该面板；客户端该上传方法还绕过通用请求，未带控制权双头。
- **影响**：恢复上传入口前存在契约与鉴权空白；上传单个 URDF 也不等于其 mesh、纹理或 package 资源一并可用。
- **建议方案**：将“控制器是否允许更换模型”列为待确认能力。若允许，定义 multipart 上传、支持格式、大小限制、资源依赖校验、覆盖 / 激活 / 持久化时机与失败回滚，明确受保护操作的双头鉴权；若不允许，前端应仅保留本地预览或控制器下载，不把遗留方法当作有效契约。
- **验收方向**：只有已确认支持并完成契约的上传才恢复入口；覆盖正常模型、无效 XML、缺失资源和无控制权，不以 mock 支持作为真实控制器实现证据。

### G04 · 实时状态 WebSocket 没有正式消息契约

- **分类 / 优先级**：协议缺失、前端问题、待控制器验证；**P1**。
- **证据**：`RobotWebSocket` 连接 `/ws/robot_state`，兼容裸对象或 `{ data: ... }`，每两秒发 `{ "type": "ping" }`；消息均尝试转换为 RobotState。完整在线路径、webhooks 和模型中无对应消息定义。HTTP 回退间隔为 20ms，初次连接三秒未成功则回退。
- **影响**：服务端的 ping/pong、错误或事件消息可能被当作状态；双方缺少频率、首帧、完整快照 / 增量、鉴权与失效检测的统一依据。网络重连后 HTTP 与 WS 的去重也是前端接入问题。
- **建议方案**：在 Apifox 中维护关联的 WS 消息说明或专用消息规范，明确握手与 Origin、消息类型、状态载荷、时间戳、序号、推送频率、心跳响应、关闭码、只读权限及失联判定；不能仅新增一个 HTTP GET 路径就声称覆盖 WebSocket。建议状态消息复用 RobotStateData，并约定回退和恢复后的单一数据源策略。
- **验收方向**：验证首帧、pong、错误消息、重复 / 乱序、静默失联和重连；前端只接受状态消息，WS 恢复时不会留下并行轮询导致重复更新。

### G05 · 控制权基础已齐全，补齐接管身份与失效后行为

- **分类 / 优先级**：已有协议需升级、待控制器验证；**P1**。
- **证据**：两个 security scheme 的真实头名为 `X-Rocos-Control-Token`、`X-Rocos-Client-Id`，48 个操作在同一 requirement 对象中要求二者同时存在。acquire 已定义 `client_id`，takeover 请求体却只有 `client_name`；HMI 两者均发送 `client_id` 和 Client-Id 头。takeover 返回的 ControlOwnerData 包含身份字段，但请求身份来源与冲突规则未说明。
- **已覆盖规则**：默认 TTL 300 秒，以响应 `ttl_seconds` 为准；成功鉴权的写请求和心跳续期，普通 GET 不续期；建议心跳默认五秒，短 TTL 不超过 TTL/3；status 不返回 token；旧 token 不能靠心跳恢复。缺 token 为 3006，无效 / 过期 / 身份不匹配为 3007，已有有效持有者的 acquire 为 3008。HMI 已有独立心跳，不应再用只读轮询续期。
- **影响与建议方案**：补齐 takeover 的 `client_id`，明确 body / header 缺失、冲突及服务端生成身份的规则；明确 TTL 到期、释放、接管时，正在点动、规划运动、Lua 和伺服分别如何处理。当前 takeover `security: []` 且描述为无条件覆盖，属于现有机制；若要引入用户权限，关联 G24，不能假称当前已有鉴权限制。
- **验收方向**：覆盖双头 AND、错误身份、源端口变化、到期、接管、旧请求迟到、GET 不续期、无 token 泄露；运行中的失权后行为与文档一致。短 TTL 下同时验证建议间隔、请求耗时与重试，而不只验证定时器间隔。

### G06 · 统一单位、位姿和坐标变换语义

- **分类 / 优先级**：已有协议需升级、待控制器验证；**P1**。
- **证据**：Pose 只列 position 与 quaternion 分量，无必填、单位、归一化或变换方向说明。RobotStateData 的 `flange`、`active_tool_frame`、`active_object_frame` 也缺这些说明。HMI 的 `PreciseMotion` 假定它们依次为 base→flange、flange→tool、base→object；内部按米、弧度计算，显示欧拉角使用 ZYX。MoveJ 的 joints 明示 rad，但没有覆盖移动关节等情况。
- **影响**：将工具局部偏移误当作基坐标绝对位姿，会改变显示和运动目标；UI 切换 mm / m、deg / rad 不能替代网络层约定。
- **建议方案**：给共享 Pose 和各字段写明单位、父子关系、右手系及 quaternion `x,y,z,w` 顺序、有效性和归一化处理；给每种运动说明目标控制点及 `tool_name` 的作用。关节标识、顺序、转动 / 移动类型与物理单位统一关联 G15。明确 HMI 欧拉显示是本地换算，不要求控制器新增欧拉字段。
- **验收方向**：用非零工具偏移、旋转工件系及非单位旋转验证显示、点动与精确运动的一致性；覆盖缺坐标系、零范数 quaternion 和混合关节类型。

### G07 · 运动参数单位、范围和圆弧组合约束不足

- **分类 / 优先级**：已有协议需升级、前端问题；**P1**。
- **证据**：五类运动均有 velocity、acceleration、jerk，但多数没有单位和范围。HMI 给关节、笛卡尔运动分别使用本地常量，不能把页面百分比视为控制器全局速度倍率。MoveC 文本支持 center_frame+theta 或 pose_via+pose_goal，并声明 pose_to 为别名，但 schema 无组合必填和互斥约束。
- **影响**：默认值和线 / 角速度含义难以验证；圆弧请求缺一半参数或同时传两种模式时没有明确选择规则。HMI 发 `pose_to` 已被协议声明为别名，不是字段拼写错误。
- **建议方案**：分清关节与笛卡尔运动各参数的物理单位、约束、缺省值和限幅 / 拒绝行为；说明混合线角目标如何规划。圆弧增加两种模式的组合校验及别名冲突规则。当前滑条只影响后续请求参数；只有确有运行中调速需求才另行定义 speed override，不把本地滑条直接映射成全局限速。
- **验收方向**：覆盖省略参数、非法数值、超限、不可达目标、圆弧缺项 / 冲突和别名一致性；运行中滑条的实际效果与页面说明一致。

### G08 · 运动任务标识与完成状态缺少闭环

- **分类 / 优先级**：已有协议需升级、协议已有但前端未接入；**P1**。
- **证据**：MoveJ 等实际引用 MotionResponse，仅返回 robot_state、control_active 和可选 motion_busy，不提供 task_id。move_status 接收可选 task_id，但 MoveStatusData.task 是空 object 或 null，缺少任务结果语义。虽然另有 TaskStatusData、MoveResponse 模型，当前运动操作没有引用它们，不能据模型存在就声称已支持异步任务闭环。wait_move 仅描述延时后轮询 FSM，无请求超时参数。
- **影响**：UI 的“已发送”不能表示某条运动已经完成，也难以区分后续运动、脚本运动或其他客户端任务；阻塞等待缺少明确终止界限。
- **建议方案**：统一当前运动的受理、执行、完成、失败、停止与暂停模型，建议响应返回可查询的命令 / 任务标识；在 move_status 中定义结果、失败原因与未知 / 过期标识行为。明确 wait_move 等待范围、超时、失权和断连语义，再由前端接入。保留旧返回字段，新增关联字段优先采用兼容扩展。
- **验收方向**：连续两次运动、暂停后继续、停止、规划失败、未知 ID、等待超时与客户端断线后重连均能区分“哪条指令处于什么状态”。

### G09 · 点动续发、速度向量与停止竞态需明确

- **分类 / 优先级**：已有协议需升级、待控制器验证；**P1**。
- **证据**：jog 默认 timeout=0.1、dir_threshold=0.99，但缺单位、范围和详细含义。cartesian 描述 twist 为线 / 角速度向量，又有独立 speed，未解释是否归一化和如何缩放。HMI 实际发单位方向向量加 speed，采用“请求完成后再等 50ms”串行续发并显式传 timeout=0.3；释放后发送 stop，迟到的 feed 完成后再次 stop。
- **影响**：续发真实周期还包含请求耗时；timeout 若按其他单位或刷新点计算会产生断续或超时歧义。跨请求的 stop 与迟到 feed 谁生效，不能由 HTTP 返回顺序保证。
- **建议方案**：明确 timeout 的秒单位、计时起点、每次有效续发是否刷新，以及超时后的减速 / 停止与状态回报。明确 joints、twist、speed、direction 的组合和混合线角向量单位，dir_threshold 的几何含义。建议为一次点动增加会话 / 序号或等价的服务端失效机制，防止已停止会话被迟到请求重启；此为建议能力，不是现有保证。
- **验收方向**：覆盖慢响应、丢包、停止先到 / feed 后到、快速切换方向、切参考系、失焦、失权与续发中断，核对服务端停止而非仅前端停止发包。

### G10 · SVD / 零空间能力不能仅用 DOF−6 推断

- **分类 / 优先级**：已有协议需升级、前端问题；**P1**。
- **证据**：jog/svd 只定义 dim_speeds 数组，无维数、单位、排序或基底连续性说明。NullSpacePanel 用 `max(0, DOF - 6)` 生成按钮，并将标量放进该长度数组。jog/nullspace 已有独立方向向量操作，但当前面板没有使用它。
- **影响**：SVD 维度与控制器雅可比秩、任务约束未必等同于固定冗余数；同一按钮跨姿态的方向是否稳定缺少依据。
- **建议方案**：描述两种接口的不同用途、维数确定方式、速度单位、基向量顺序和奇异状态行为；建议由能力 / 状态提供支持维数及不可用原因，前端据此生成按钮，不把新增接口当作首选。
- **验收方向**：覆盖六轴、七轴、奇异姿态及不支持配置；维数错误被明确拒绝，末端约束和方向行为符合定义。

### G11 · 控制命令受理、状态转移和成功条件需统一

- **分类 / 优先级**：已有协议需升级、前端问题、待控制器验证；**P1**。
- **证据**：RobotStateData 有 ENABLING、RESETTING、STOPPING 等过渡态，但多数写操作无状态前置条件与完成时机。reset 已说明仅 ERROR_STATE、最终 STOPPED 或 ERROR_STATE；ResetButton 的注释却兼容“success=false、code=-2307 仍执行”，轮询时只要离开 ERROR_STATE 就显示成功。该特殊返回未在在线 reset 定义中说明，仅是前端兼容假设。
- **影响**：若返回只表示受理，前端乐观更新 enabled 或把 RESETTING 当复位成功就会过早提示。pause/resume/stop 的适用任务范围也需明确。
- **建议方案**：增加状态前置条件和转移表，说明成功响应是完成还是受理、过渡态如何查询、重复命令如何处理，以及运动停止与脚本停止的关系。优先修正文档和前端成功条件；只有实际异步行为需要时才扩展操作标识。特殊错误码需经控制器验证，不能从注释直接写成协议。
- **验收方向**：覆盖长时间使能 / 复位、过渡态、无效状态、超时和重复命令；复位最终 STOPPED 才判完成，ERROR_STATE 判失败，RESETTING 仍显示处理中。

### G12 · 遥测缺测、时间与采样质量需要正式约定

- **分类 / 优先级**：已有协议需升级、前端问题；**P1**。
- **证据**：RobotStateData.timestamp 已定义为 epoch seconds，JointState 含 position、velocity、torque、load_torque，但大部分未列 required、单位或有效性；前端类型兼容 acceleration、load，在线模型没有这两个字段。采集器转为毫秒；缓冲区同时间戳去重、时间倒退清空，最多十分钟 / 每通道 30,000 点。REST / WS 映射会把部分缺失状态值填零或单位位姿。
- **影响**：缺测可能被显示成真实零值，低时间精度可能合并多帧，时钟校正可能清空数据；当前 CSV 只是浏览器会话缓冲，不是控制器历史导出。
- **建议方案**：约定必要字段、物理单位、缺测 / 不可用表达、快照一致性、时间精度、序号及实际采样频率；明确 acceleration 是否支持，统一 load 与 load_torque 的兼容策略。前端保留不可用信息，处理时间跳变和重复帧。若以后要求跨重连历史或完整录波，再新增历史查询 / 导出能力。
- **验收方向**：检查缺字段、同时间戳多帧、时间倒退、采样频率变化、断流和缺测 CSV；单位换算正确且缺测不变成零值。

### G13 · 安全状态、报警和日志缺少可用协议

- **分类 / 优先级**：协议缺失；**P1**。
- **证据**：RobotStateData / HardwareState 只提供 FSM、总线状态和关节状态码，未定义急停回路、安全门、保护停止、活动报警集合、历史事件或日志操作；TeachShell 显示安全与报警 unknown，Diagnostics 使用示例行。
- **影响**：能知道机器人处于 ERROR_STATE，却无法可靠说明原因、是否可复位及发生顺序；不能用“无字段”推导“安全正常 / 无报警”。
- **建议方案**：提供只读安全状态与有效性、活动报警，以及有时间范围 / 游标的报警历史和日志查询；建议事件含稳定标识、时间、来源、严重度、码、描述和恢复状态，状态流按需推送变化。报警确认、清除与机器人 reset 分开定义，新增写操作明确权限。软件 stop 的协议不能描述成安全急停功能。
- **验收方向**：覆盖未知 / 不支持、多个报警、恢复后历史保留、分页去重、断线补读；UI 可追溯故障原因，并继续区分软件停止与安全回路状态。

### G14 · 模型资源格式与缓存一致性不足

- **分类 / 优先级**：已有协议需升级、待控制器验证；**P1**。
- **证据**：GET urdf 已正确声明 `text/xml` 字符串；mesh 声明 octet-stream 二进制、path 必填并支持 package://，说明只提 STL。HMI 会话缓存按控制器地址与 URDF 文本复用；模型加载器还涉及 [资源加载](../src/core/RobotPreview.ts)。协议无资源清单、模型版本、hash、缓存验证头或模型变化事件。
- **影响**：URDF 文本不变而同路径 mesh 被替换时无法识别；缺失资源、DAE / 纹理等格式支持无法从当前协议确认，不能因本地 Baxter 模型存在就认定在线支持。
- **建议方案**：补充允许的格式、package 解析与相对路径规则、缺资源响应；建议增加模型版本 / 内容 hash、资源媒体类型和缓存验证机制，说明 URDF 与资源是否属于同一一致快照。保留 XML / 二进制原始成功响应，不强制改成 JSON 包装。
- **验收方向**：覆盖 package://、带空格路径、缺失资源、同路径资源更新、模型切换及实际支持的格式；新旧资源不会被混装，缓存命中与失效可验证。

### G15 · 缺少控制器能力、版本与运行限制发现

- **分类 / 优先级**：协议缺失、前端问题；**P1**。
- **证据**：GET info 的 RobotInfoData 只有关节传动和编码参数，没有控制器版本、协议 profile、能力开关或运行限值。客户端却根据未入 schema 的 `api_profile === 'legacy_robot'` 决定是否默认发送笛卡尔 jerk。关节显示从 URDF 读范围；运动命令仍用本地速度常量和角度输入范围；阻抗界面固定七轴。
- **影响**：能连上 GET info 不等于支持全部命令，模型范围也不等于控制器当前有效软限位；前端不能按机器人能力可靠启用功能。
- **建议方案**：扩展 info 或提供独立 capabilities，建议包含控制器 / API profile 版本、支持功能、关节稳定标识与顺序、类型、单位、有效位置 / 速度 / 加速度 / jerk 限制，以及支持的工作模式和资源格式。优先覆盖当前兼容分支和固定值，不要求一次设计所有硬件配置。前端使用已发布能力并保留老控制器降级逻辑。
- **验收方向**：新旧 profile、不同 DOF、移动关节、缺能力字段及不支持 jerk 均可识别；能力声明与实际拒绝结果一致，UI 不把缺失值当成无限制。

### G16 · 坐标系管理已有，升级别名、持久化和活动配置规则

- **分类 / 优先级**：协议已有但前端未接入、已有协议需升级；**P2**。
- **证据**：线上已有工具 / 工件名称列表、单项 GET / POST / DELETE、激活以及 YAML load/save；无需再设计一套重复 CRUD。FrameSelector 当前只选 BASE / FLANGE / TOOL / OBJECT 类型。tool_frame / object_frame 的 POST 同时写 `required: [name, frame]` 和 `pose` 别名，导致仅传别名不满足 schema；object 名称约束也不如 tool 完整。
- **影响**：页面无法管理控制器命名库；别名校验与描述不一致；删除活动坐标系、覆盖后的生效时机和 save 是否持久化缺明确规则。
- **建议方案**：前端优先接入现有列表、CRUD 和激活；协议统一名称约束、别名组合校验、活动项删除 / 覆盖行为，以及设置、激活和落盘的关系。frames/load/save 的 path 是控制器文件路径，不能直接等同于浏览器文件上传下载；需要文件传输时再补资源接口。
- **验收方向**：覆盖新建、查询、重名更新、非法名、活动项删除、仅 pose 别名及两个别名冲突、保存重启与加载失败回滚。

### G17 · 脚本列表下载已齐全，缺持久编辑闭环

- **分类 / 优先级**：协议缺失、已有协议需升级；**P2**。
- **证据**：list 返回 scripts 相对路径，download 以 filename 查询并返回 text/plain；两者 HMI 已接入。upload 明确“仅加载到内存，不写文件系统”，Programming 的上传按钮和运行前上传都复用它；没有持久保存、重命名、删除操作。
- **影响**：在 HMI 新建 / 编辑后上传不会按契约出现在文件列表里，也不保证重启保留；不能把 upload 的 filename 理解为已写入控制器文件。
- **建议方案**：保持 upload=编译加载的现有语义，另行定义受保护的文件保存 / 重命名 / 删除能力，说明路径范围、覆盖规则、编码、大小及失败结果；建议文件元数据带修改时间和 revision/hash，用于避免覆盖较新版本。下载继续返回原始 Lua 源码，持久保存后可通过已有 list / download 回读。
- **验收方向**：区分内存加载与文件保存，覆盖重启、重名 / 冲突版本、无效相对路径和正在运行文件的修改；列表与下载的只读权限保持明确。

### G18 · 接入脚本状态与断点，再补程序步骤监控

- **分类 / 优先级**：协议已有但前端未接入、已有协议需升级、前端问题；**P1**（基础状态接入），**P2**（步骤监控）。
- **证据**：GET script/status 和三个 breakpoint 操作均已定义；ScriptStatusData 必填 state、script_id、filename、line、error、motion_active、breakpoints，已有明确脚本状态枚举。客户端运行等方法声明 Promise<void>，页面没有利用返回状态；Programming 显示的是机器人 FSM。Execution 每 900ms 增加本地 demoStep，不读取控制器进度。
- **影响**：脚本 PAUSED / COMPLETED / FAILED 与机器人状态可能不同；以行号推算百分比或把本地演示步骤当作实机进度都不可靠。
- **建议方案**：先在客户端暴露并使用 ScriptStatusData，接入现有状态和断点操作，说明 line 是当前 / 下一行、无活动行时的值、脚本标识生命周期、单步有效行与断点命中语义。步骤可视化另行建议提供稳定的执行实例标识、步骤 / block 标识映射与运行事件；循环和条件分支不强制给出虚假百分比。无需新增重复 run/pause/stop 接口。
- **验收方向**：完整验证 EMPTY→LOADED→RUNNING、暂停 / 单步 / 断点、完成 / 失败 / 停止、重复运行和重连；执行页无真实数据时显示不可用，不运行本地进度冒充实机。

### G19 · Blockly 上线需要 Lua 绑定说明和项目关联

- **分类 / 优先级**：前端问题、协议缺失；**P2**。
- **证据**：BlockEditor 的机器人积木生成 `-- Preview ...` 注释，并标注 API mapping 未实现；工作区 JSON 使用本地 schemaVersion=1 保存。当前 HTTP 协议定义 Lua 源码加载执行，但没有给出积木所需的机器人 Lua 函数签名、等待语义和点位 / I/O 访问约定。
- **影响**：HTTP 能执行脚本不代表当前积木已能生成有效机器人程序；为每个积木加一个 REST 接口不能自动解决脚本内部调用问题。
- **建议方案**：先补充版本化的 Lua 运行时绑定文档，明确运动、等待、点位引用和 I/O 函数、单位及异常传播，前端生成真实代码并复用已有 script 执行。建议保留 Blockly 工程、生成源码版本及 block→行映射；只有跨终端工程管理需要时再增加项目保存接口。
- **验收方向**：同一工程可导入、导出、重生成；预览源码不得进入实机执行；生成程序的错误行和断点可定位回积木，运行依赖的点位 / I/O 能力可检查。

### G20 · 示教点库缺协议，本地点模型不够表达可执行目标

- **分类 / 优先级**：协议缺失、前端问题；**P2**。
- **证据**：ContextPanel 连接时取关节和 flange.position，再转成 deg、mm 保存；TeachPoint 只有 id、name、joints、position、source，没有姿态 quaternion、工具 / 工件上下文、机器人标识或版本。记录、重命名、删除都只写本地 teachStore；完整在线路径无点位库操作。
- **影响**：换浏览器或控制器无法同步点位；仅 XYZ 不能恢复完整笛卡尔姿态，演示点与真实采集点也不能未经校验混用。
- **建议方案**：定义控制器点位库的列表、读取、保存、重命名与删除能力，建议保存 SI 单位关节值、完整 Pose、目标控制点、工具 / 工件引用和来源；关联机器人 / 关节顺序与 revision，明确采集快照来源和有效性。点位执行复用已有运动接口或脚本绑定，避免再造运动指令族。
- **验收方向**：记录后可回读完整位姿，控制器重启保留；不同机器人、示例点、丢失坐标系或旧版本引用可识别，不静默执行；本地历史草稿需显式转换单位和补齐姿态。

### G21 · I/O、外围设备与工具负载缺线上能力

- **分类 / 优先级**：协议缺失；**P2**。
- **证据**：Devices 的 DI / AI 为常量、DO 只切换本地 outputs，夹爪 / 相机 / 输送线是示例卡片；工具名称与 payload 仅存本地。完整协议无相应操作，NamedFrame 也仅含 name 和 frame，不能承担负载配置。
- **影响**：页面操作不影响控制器，执行流程中的“等 DI / 写 DO / 夹取”无法闭环；工具坐标和工具质量是不同能力。
- **建议方案**：分别定义 I/O 通道发现与状态、受保护输出写入、写后回读，包含数字 / 模拟类型、地址、范围、单位、有效性及失联值；等待输入的超时与取消由 Lua 绑定或执行模型说明。工具配置建议关联 TCP 与质量 kg，并按动力学需求补质心 / 惯量、生效模式和持久化规则。外围设备先定义实际支持的设备类型与状态，再决定通用设备层或专用操作，不把示例卡片当作真实硬件需求证明。
- **验收方向**：I/O 通道数量不是固定八路，覆盖只读输入、越界输出、写入失败 / 回读、等待超时及失权；负载配置可回读，TCP 切换与负载生效关系明确。相机等无实现支持时显示不可用。

### G22 · 标定计算尚未实现，坐标设置别名不等于标定

- **分类 / 优先级**：协议已有但前端未接入、已有协议需升级、待控制器验证；**P2**。
- **证据**：POST calibration/pose、run 和 GET calibration/result 均 deprecated=true，描述明确未实现并返回 1004。calibration/tool、object 在线 deprecated=false，摘要说明等同对应 robot/*_frame 设置；客户端却注释为已废弃。
- **影响**：调用坐标设置不能获得采样、拟合误差和标定结果；也不能仅根据前端注释宣称在线所有 calibration 操作都已废弃。
- **建议方案**：先统一别名的弃用状态与迁移说明。只有规划真实标定功能时，再设计采样会话、标定方法、计算、质量指标和结果应用流程；应用结果复用现有坐标系管理。不要在本次评审中删除操作或关联模型。
- **验收方向**：能力发现可识别未实现操作；未实现返回、坐标设置与标定计算明确区分；将来标定失败不覆盖现有有效坐标。

### G23 · 拖拽与伺服入口已有，补运行约定后再开放 UI

- **分类 / 优先级**：协议已有但前端未接入、已有协议需升级；**P2**。
- **证据**：drag/start、stop 和 servo/mode、start、stop 已存在，前者有 flag、direction、速度 / 加速度，后者描述为 localhost UDP 接收 MotionGeneratorCommand。协议未提供 UDP 报文 schema、版本、频率、序号和超时行为；拖拽与导纳工作模式的关系也未说明。
- **影响**：不能因没有按钮就认定 HTTP 入口缺失；同时，浏览器无法直接按普通 Web API 发送原生 UDP，已有启动接口不等于 HMI 可完成伺服控制。
- **建议方案**：补齐拖拽的前置模式、方向 / 轴语义、停止与失权行为；伺服补充 UDP 协议、绑定地址、周期、包有效性和停机恢复。当前需求无需强行新增浏览器伺服通道；若未来要接入，应先确定运行端与桥接能力。
- **验收方向**：覆盖不支持模式、重复 start/stop、丢包 / 超时、失权、退出后的 FSM；验证真实运行环境而非仅测试 HTTP 启动成功。

### G24 · 本地 admin 展示不构成控制器用户权限

- **分类 / 优先级**：协议缺失、前端问题；**P2**。
- **证据**：HeaderAccount 固定一个本地 admin，无登录或角色查询；在线仅有控制权双凭据，acquire 与 takeover 无用户鉴权要求。协议会记录 client_name / User-Agent，但这些自报值不是已验证用户身份。
- **影响**：当前“管理员”只是展示，不能据此实现或宣称控制器 RBAC；单持有者控制权解决并发持有，不自动解决谁允许接管或修改配置。
- **建议方案**：若产品上线用户权限体系，先明确操作者、管理员及接管授权，再增加身份、有效权限与审计关联；与控制权会话保持职责清晰。若继续采用可信网络部署，文档明确此前提，前端避免把本地标签作为权限依据。本项是对已有用户展示的后续建议，不要求本次引入登录系统。
- **验收方向**：权限来自可验证来源，普通用户与管理员的受限操作由服务端校验；接管者及配置变更能关联真实主体，或明确系统未提供该能力。

### G25 · 公共错误响应与 schema 完整性需统一

- **分类 / 优先级**：已有协议需升级、前端问题、待控制器验证；**P1**。
- **证据**：66 个操作都只声明 200；StandardResponse 仅说明业务码大类，没有逐操作错误与 HTTP 状态映射。除 G02 外，刚度 / 阻尼响应为空对象模型；多数状态 / Pose 字段没有 required。下载 Lua、URDF 和 mesh 各有正确的原始成功媒体类型，但没有失败媒体类型约定。HMI 的 Lua 下载兼容 HTTP 200 JSON 业务错误，通用 JSON 请求与部分二进制方法的 HTTP 错误处理并不一致。
- **影响**：生成客户端、自动校验和错误展示缺少稳定依据；若真实返回 401 / 403 而无匹配 JSON，控制权心跳当前会按网络错误重试，而非按 3006 / 3007 立即失权。没有失败定义并不表示全部实际失败都返回 200。
- **建议方案**：统一描述现有 HTTP 与业务码映射，先确认真实行为再补常见错误响应、必需字段和错误示例；原始下载成功仍保持 text/plain、text/xml、octet-stream，错误明确 Content-Type 与包装。新增请求追踪标识和结构化错误详情可作为兼容扩展。复核保留的旧模型与当前操作引用关系，但未经独立授权不删除它们。
- **验收方向**：成功、参数错误、无控制权、失权、非法状态、内部失败和资源不存在都按契约解析；验证下载失败不会被当作源码 / mesh；任何 HTTP 映射变更同步检查客户端与现有回归用例。

## 4. 分阶段升级路线与兼容约束

| 阶段 | 建议工作 | 完成标志 |
| --- | --- | --- |
| 第一阶段：解除当前契约冲突 | G01、G02；同时处理 G25 中直接影响现有调用的响应定义 | 阻抗应用、模式切换的真实请求与响应有唯一契约，前端可按其解析；不依靠未记录的返回形态 |
| 第二阶段：补齐当前控制与观测语义 | G04–G15、G25；接入 G18 的基础脚本状态 | 实时状态与 HTTP 快照一致；坐标、单位、点动生命周期和失权行为可验证；任务与错误可追溯，显示有可信有效性 |
| 第三阶段：复用已有接口完成管理接入 | G16、G18 的断点接入、G22 的弃用状态整理 | 坐标库和脚本调试走已有接口；前端未接入不再误列为协议缺失 |
| 第四阶段：分功能上线预览闭环 | G17、G19–G21、G18 步骤监控、G24；G03、G22 标定计算、G23 按产品需求安排 | 点位、I/O、负载、程序资源与执行状态可持久回读，预览标识只在已验证的真实能力上线后移除 |

兼容原则：

- 本文不更改远端定义、应用版本或业务代码；后续接口变更需在 Apifox 维护并 MCP 回读，不新增受维护的本地 OpenAPI 副本。
- `ControlToken` 与 `ClientId` 保持同一 security requirement 的 AND 语义；新增受保护写操作沿用该约定。不要把“两个独立 requirement”误当成双凭据必须同时存在。
- 默认值、已有别名、阻尼参数名、错误状态与持久化语义可能影响老控制器；先记录实际行为，再通过兼容字段、明确 profile 或弃用周期迁移。不能仅为匹配前端而覆写控制器事实。
- 保留原始 XML、Lua 文本和二进制资源成功响应；API 版本与 HMI 包版本分别评估，不在本报告指定版本号或删除旧模型。
