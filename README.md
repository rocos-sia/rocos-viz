# ROCOS HMI

ROCOS 机器人可视化与控制 Web 前端。通过浏览器查看机械臂三维模型、实时状态和数据曲线，并连接 ROCOS 控制器执行点动、精确运动与参数配置。

项目目前处于 **rc 测试阶段**，当前版本以 [package.json](package.json) 为准。本仓库包含前端和用于模型展示的简易测试服务；完整运动控制需要连接提供 ROCOS HTTP API 的后端。

## 功能概览

| 功能 | 说明 |
| --- | --- |
| 三维可视化 | 从控制器加载 URDF 及网格，随关节状态更新模型；支持旋转、缩放、预设视角、坐标轴、线框、地面和轨迹显示 |
| 状态监控 | 显示连接、使能、工作模式和机器人状态；优先使用 WebSocket，连接异常时回退到 HTTP 轮询 |
| 控制权管理 | 连接后申请控制权，按服务端建议间隔发送心跳；显示控制权状态，支持确认后接管和断开时释放 |
| 点动控制 | 关节与笛卡尔点动；支持 BASE、FLANGE、TOOL、OBJECT 参考系，以及冗余机械臂的 SVD 零空间点动 |
| 精确运动 | 提供 MoveJ、MoveJ_IK、MoveL、MoveL_FK 指令入口，以及速度比例、暂停、恢复和停止操作 |
| 实时曲线 | 四路图表，可选择关节位置、速度、力矩、负载和法兰位置数据 |
| 工具与标定 | IO 与设备 → 末端工具：真实工具增删改、重命名、激活及 YAML 持久化；六点采集、误差校验、明确保存；全局负载/质心读取与保存 |
| 阻抗参数 | 读取与设置关节、笛卡尔空间刚度和阻尼，支持 JSON 导入、导出 |
| 界面设置 | 中英文切换、明暗主题、控制面板折叠与宽度调整、曲线浮窗拖动 |

### 工具管理与六点法标定

入口为“IO 与设备 → 末端工具”，手动示教页也提供“工具管理”按钮。需要支持六点标定和持久化工具 API 的新版 App；使用旧 App 时会提示升级。

先用四种不同法兰姿态，让工具尖端对准同一参考点，采集 P1–P4；保持 P4 的方向，分别沿期望工具 +X、+Z 移动到 P5、P6。每次停止后采集真实关节/法兰数据，六点齐全再计算。默认最大误差 1 mm，界面显示 RMS、最大误差和条件数。计算不会自动改变 TCP，检查结果后“保存为工具”，再按需要“设为当前工具”。可以切回示教页调整姿态，返回时回读会话；重采集立即清除旧结果，断开或更换控制权会清空草稿。

工具 XYZ/RPY 跟随全局显示单位，传输使用米和四元数。新增、编辑、重命名、删除和激活均持久化到 App 的 `robot.frames`（默认配置目录下 `frames.yaml`），失败会显示错误；页面不会在本地伪造成功结果。写操作要求控制权及 IDLE/STOPPED 状态。工具质量与质心是控制器全局负载，独立于命名 TCP，切换工具不会自动切换负载。

手动示教顶部“显示坐标系”选择“工具”时，显示当前 TCP 相对基坐标系的实时位姿，优先直接读取 App 的 `state.tcp`；法兰显示仍使用 `state.flange`。工具列表中的位姿是固定的“法兰到 TCP”偏置。新版 App 返回 `tcp: null` 时显示不可用；旧 App 缺少该字段时兼容在前端合成。无活动工具时 TCP 按法兰处理。查询指定工具可使用只读 `GET /api/robot/tcp?name=tool1`，省略 name 使用当前工具，不会切换激活工具。

连接控制器并加载模型后，3D 视图和总览预览会自动显示当前工具的 TCP 坐标轴（X 红、Y 绿、Z 蓝），标注 `TCP · 工具名`，随实时位姿和工具切换更新。工具轴独立于关节轴开关；未激活工具、断开连接或 TCP 位姿不可用时隐藏。

完整数学约定与后端部署步骤见 App 的 `docs/tool_calibration.md`；接口以 [Apifox](https://app.apifox.com/project/8387612) 为准。浏览器流程测试：`npx playwright test test/browser/tooling.spec.ts`（模拟控制器，无真实运动）。

### 当前功能边界

- 系统设置中已实现阻抗参数页；系统状态、安全、坐标系、IO 和维护页目前仅有导航入口。
- API 客户端已封装 Lua 脚本上传、运行、暂停、恢复、停止、单步及列表、源码下载接口；脚本编辑组件及脚本列表、下载入口尚未接入当前主界面。
- 部分控制界面按七关节机械臂设计；其他自由度机器人的适配需结合具体模型与控制器验证。

## 快速开始

### 环境准备

- Node.js：需要 **20.19+（20.x）或 22.12+**；已使用 **Node.js 24.22.0 / npm 11.19.1** 完成安装、测试和生产构建。
- 支持 WebGL 的桌面浏览器，并开启硬件加速。
- 可访问的 ROCOS 控制器；没有控制器时，可使用下方测试服务查看模型和模拟状态。

### 安装与启动

```bash
git clone https://github.com/rocos-sia/rocos-viz.git
cd rocos-viz
npm ci
npm run dev
```

默认打开 `http://localhost:5173`。Vite 默认将 `/api` 和 `/ws` 请求代理到本机 `127.0.0.1:8080`。

### 安装提示

- `packages are looking for funding` 是依赖的赞助提示，不影响运行。
- `whatwg-encoding@3.1.1 deprecated` 来自 `blockly → jsdom` 的间接依赖，表示该包已弃用，不代表安装失败。当前保留 Blockly 12 的兼容性，等待上游依赖迁移；不要直接将它强制替换为 API 不同的 `@exodus/bytes`。
- 新版 npm 默认拦截尚未授权的依赖安装脚本。本项目通过 `package.json` 的 `allowScripts` 按版本授权 esbuild 的二进制安装校验脚本。以后升级 esbuild 如再次出现提示，先运行 `npm install-scripts ls` 检查，审阅后执行 `npm install-scripts approve esbuild`，再运行 `npm rebuild esbuild`；授权命令本身不会执行安装脚本。旧版 npm 不支持这些命令，无需执行。详见 [npm 安装脚本授权说明](https://docs.npmjs.com/cli/v11/commands/npm-install-scripts/)。
- 出现漏洞提示时先运行 `npm audit` 查看来源。依赖修复后需同步提交 `package.json` 和 `package-lock.json` 并运行测试、构建；不要直接运行 `npm audit fix --force`，它可能引入不兼容的主版本升级。

### 连接机器人后端

支持两种连接方式：

**通过开发代理连接**：启动时指定后端地址，例如以下 Bash 命令：

```bash
ROBOT_HOST=192.168.1.100 ROBOT_PORT=8080 DIAGNOSTICS_PORT=8082 VITE_PORT=5173 npm run dev
```

在页面连接对话框中填写 `127.0.0.1`，即可使用同源代理。此时实际后端地址和端口由启动环境变量决定，更换代理目标后需要重启 Vite。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `ROBOT_HOST` | `127.0.0.1` | 开发代理指向的控制器主机 |
| `ROBOT_PORT` | `8080` | 开发代理指向的控制器端口 |
| `DIAGNOSTICS_PORT` | `8082` | 日志查询和实时日志流的诊断端口 |
| `VITE_PORT` | `5173` | 前端开发服务端口 |

**浏览器直连控制器**：在连接对话框中填写控制器的非回环 IP 或主机名及端口，请求将直接发往该地址。日志接口使用控制器诊断端口（默认 `8082`），远程部署时需确保该端口可访问。后端需要支持跨域访问，并允许 `X-Rocos-Control-Token`、`X-Rocos-Client-Id` 等请求头。HTTPS 页面需配合可访问的 HTTPS/WSS 后端或同源反向代理。

### 日志连接与端口

机器人连接成功后，应用会自动查询日志并建立一条 SSE 实时订阅，**默认连接控制器的诊断端口 `8082`**，无需单独点击日志连接按钮。“手动示教”底部的“日志”和“监控诊断 → 日志”共享同一份记录、排序和订阅状态。切换页面不会中断订阅，其他页面期间收到的日志也会保留；断开或切换控制器时会关闭原订阅并清理记录。

| 连接方式 | 日志请求目标 | 端口配置 |
| --- | --- | --- |
| 开发模式，连接框填写回环地址（如 `127.0.0.1`） | Vite 将 `/api/logs` 及其子路径代理到 `ROBOT_HOST:DIAGNOSTICS_PORT` | 默认 `8082`，可通过启动环境变量修改 |
| 开发模式，连接框填写非回环地址 | 浏览器直连所填控制器地址的 `8082` 端口 | `DIAGNOSTICS_PORT` 不影响直连请求 |
| 生产构建 | 浏览器直连所填控制器地址的 `8082` 端口 | 当前尚未提供界面端口配置 |

控制 API 默认使用 `8080`，诊断日志使用独立的 `8082`。连接框中的控制端口不会改变日志端口；Viz 不会自动读取 App 的 `diagnostics.port` 配置。

如果 App 将 `config/config.yaml` 中的 `diagnostics.port` 改为 `18082`，可通过开发代理连接：

```bash
cd ~/sia/rocos-viz
ROBOT_HOST=127.0.0.1 ROBOT_PORT=8080 DIAGNOSTICS_PORT=18082 npm run dev
```

连接框填写 `127.0.0.1` 以使用该代理。修改启动环境变量后需重启 Vite。远程控制器需同时设置 `ROBOT_HOST` 为其地址，并确保诊断端口可访问。

首次查询最近 100 条告警，通过 SSE 追加新记录，按事件 ID 去重，最多保留 200 条。当前 App 的查询和实时接口仅提供 `warn/error/critical`；普通 `info` 日志保存在 App 日志文件中。实时连接断开时自动重连，缓存缺口或控制器重启会显示提示；查询失败可点击刷新重试。离线时显示标注为示例的数据。

在“监控诊断 → 日志”右上角可“查看最新日志文件”或“下载日志文件”。两者通过同一诊断地址的 `GET /api/logs/file/latest` 读取 App 当前文件的快照，包含 `info` 等文件配置允许的级别。预览显示文件名、快照时间和前 256 KiB 文本，只对级别标签着色；点击预览中的刷新会重新读取快照。下载保存完整原文件并保留服务端文件名。该入口读取当前文件，不合并已轮转的历史文件；断开连接或切换控制器会取消读取并关闭预览。

2026-10-23 已将三个日志接口及负载参数读取、设置、保存接口补入 [Apifox ROCOS API](https://app.apifox.com/project/8387612)（主分支、模块 `7912103`、API 版本 `3.0.0`）。经 MCP 刷新回读确认，当前共 67 条路径、72 个操作；日志接口无需控制权，两个负载写接口同时要求控制令牌和客户端标识。

### 基本操作

1. 在连接对话框中填写地址和端口，点击连接。成功后自动获取控制器 URDF 模型并开始接收状态。
2. 查看顶部控制权状态。若控制权由其他客户端持有，可继续观察；需要操作时，通过接管按钮确认接管。
3. 取得控制权后使能机器人，选择工作模式、参考系及速度比例，在右侧点动或精确运动页操作。实际可用操作由控制器状态决定。
4. 打开曲线窗口查看实时数据，点击图表选择数据源；通过工具栏切换视角、显示选项、语言和主题。
5. 在系统设置的阻抗参数页读取当前值，编辑后应用；JSON 导入后仍需点击应用才会写入控制器。
6. 结束使用时，通过界面的断开连接操作释放控制权。机器人进入 `ERROR_STATE` 时，界面会显示复位入口。

## 无控制器时查看模型

仓库提供基于 Python 标准库的简易 URDF 测试服务，已验证 Python 3.10 可用，无需安装额外 pip 依赖。在仓库根目录另开终端运行：

```bash
python3 server/urdf_server.py --port 8080 --urdf server/models/talon/robot.urdf
```

再运行 `npm run dev`，在页面连接 `127.0.0.1:8080`。也可以省略 `--urdf`，使用默认的简单机械臂模型。

测试服务提供 URDF、网格文件和模拟状态等接口，**不提供完整控制权、运动、脚本和阻抗接口**。它适合查看模型及曲线，控制权相关请求可能返回 404。该脚本依赖 Python 的 `cgi` 模块，运行环境需提供此模块。

## 常见问题

- **连接失败**：确认控制器地址、端口以及 `/api/robot/info` 是否可访问；使用开发代理时检查启动环境变量，直连时检查浏览器网络面板中的跨域错误。
- **模型空白或网格缺失**：检查 `/api/robot/urdf`、`/api/robot/urdf/mesh` 是否可访问，以及 URDF 中引用的网格是否由控制器提供。
- **无法启动三维视图**：开启浏览器硬件加速，检查 WebGL 和显卡驱动。三维视图异常时，控制面板仍可显示。
- **操作提示没有控制权或令牌失效**：检查顶部持有者状态，确认是否被其他客户端接管或会话已过期；按需重新取得控制权。
